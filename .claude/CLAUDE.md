# lfg — Project Instructions

lfg runs many concurrent Claude Code agent sessions on a single host, with a Bun server and an iOS client. The hazards below come from real sessions burning time rediscovering them.

## Architecture hazards

- **Single-process Bun server.** One event loop serves all HTTP. A long-lived PTY/terminal websocket (e.g. opening the Terminal tab) can saturate it — HTTP stalls 20s+ and a restart loses in-memory session tracking. Treat embedded terminal/PTY surfaces as **capture-once-then-leave**; don't hold them open during other work.
- **A "previously-fixed" bug that recurs is usually a deploy gap, not a code bug.** Bun has no hot-reload and the `serve` process is long-lived (restarts are deferred because they drop in-memory session tracking), so the running code routinely lags source. Before re-debugging already-correct, unit-tested code, compare the running process start time (`ps -eo pid,lstart | grep '[c]li.ts serve'`) against the fixed file's mtime (`stat -f %Sm src/<file>.ts`). Process older than the fix → restart (`serve-forever.sh` respawns on child exit), don't re-debug.
- **No `/proc` on macOS.** `listSessions` in `src/sessions.ts` enriches sessions via `/proc/<pid>/cwd`, which is Linux-only. On macOS, CLI/tmux sessions won't enumerate — this is expected, not a bug. Grep source for platform assumptions (`/proc`, `systemd`, `launchd`, `pgrep`) before theorizing about missing state.
- **Session state has two owners, and `closed` is the awkward one.** `busy`/`prompt` come from `journal-pump.ts` (pane scrape / aisdk registry / transcript freshness) and `status` from `computeStatus` in `sessions.ts` (`"blocked"` = an upstream **API error** — logged out, out of credits — *not* a user pause). `closed` is computed by the server too (`listResumable` excludes live ids, stamps `closed: true`), but only ever means **"closed on this host"**: `~/.claude/projects` is synced and a server has no peer awareness (hosts are client-side config), so host B enumerates host A's transcripts and would call A's *running* session closed. `MultiHost.reconcileResumable` drops that phantom using live ids from every host — that filter cannot move server-side without giving servers peer awareness. Any consumer deriving state must mirror `SessionStore.group(for:)`'s precedence (`closed` → prompt → `isBlocked` → `busy`), not re-invent it; a parallel ladder in the Live Activity snapshot shipped a bug where ended sessions read "running" forever.
- **A live question's prose exists ONLY on the tmux pane — and every journal delta needs a REST baseline.** Claude Code does not flush the assistant turn containing an interactive tool (AskUserQuestion, permission, plan approval) to its transcript until the user answers; while it's live the prose is on disk *nowhere*. `parsePrompt`'s pane-scraped `context` is the only source, and Claude runs in the **alternate screen** (`history_size == 0`), so `capture-pane -S -N` gives you nothing extra — only what currently fits. Hence lfg spawns panes at `PANE_COLS`×`PANE_ROWS` (`paneSizeArgs`) and the pump keeps them there (`ensurePaneRows`): tmux does **not** restore `default-size` after a client detaches, so one Terminal-tab visit silently re-breaks capture forever. Separately, prompt state reached clients only as a journal `prompt` **delta**, and a cursor starts at the head — so a question asked before the client connected never arrived and the panel never appeared. Any pump-owned state a client renders needs BOTH the delta and a snapshot field arbitrated by `JournalFreshness` (`busy`/`busyStatedAt`, `prompt`/`promptStatedAt`); a delta alone is a bug waiting for the next cold launch. **A single capture is not enough and pane size cannot save you:** a long preamble is taller than the pane, so the head is gone by the time the selector renders — `PaneStitcher` (`pane-history.ts`) rebuilds it from the ~1Hz captures the pump already takes, because the head WAS on screen mid-stream. Do not try to fix this by resizing: **Eugene's real sessions come from the `cy`/`cx` shell functions in `~/.zshrc`, which bypass lfg's spawn path entirely and are always ATTACHED**, so both `paneSizeArgs()` and `ensurePaneRows` (which skips attached panes on purpose) miss them. Verify any pane fix against `tmux ls` reality — geometry and attachment of the actual live sessions — never against a session you just created through the API. See `.claude/diagnosis-question-preamble-invisible-20260807.md` and `.claude/diagnosis-question-preamble-round2-20260809.md`.
- **One sessionId can have two live processes, and every per-session map assumes it can't.** Two `claude` procs in different panes each write `~/.claude/sessions/<pid>.json` naming the SAME id (an in-TUI `/resume` of a session another live proc is on). Separately, `--resume X --fork-session` forks carry X on the command line while owning a different id, so until each fork's pidfile is readable `listSessions`' `--resume` fallback makes every fork look like its parent. Both shapes produce duplicate rows, and sessionId keys *everything* downstream — the push watcher's `prior` map, journal baselines, unread, leases, sendq. The watcher's two rows overwrite each other every tick, so their differing observations read as a transition: one reelly pane on an AskUserQuestion + one idle at the composer = a "needs input" push every ~12s forever. `resolveSessionOwners` in `sessions.ts` collapses them (authoritative claim beats guessed; newest binding wins among authoritative, OLDEST process wins among guesses — forks are the newcomers), and `runPushTick` skips repeat sids as a backstop. `resolvePaneOwners` does NOT cover this: it groups by pane, and these are different panes.
- **Client state is latched — the journal must retract, not just stop.** Clients overwrite `busy`/`prompt` only on a newer event, so a session that vanishes from `listSessions` (pane killed, transferred) strands its last value forever. `appendDisappearanceRetractions` in `journal-pump.ts` emits `busy:false`/`prompt:null` before `deltas.forget(sid)` — order matters, forget clears the baselines the change-checks read. Retract only what was actually asserted (`lastBusyValue`/`hadPrompt`); `busyChanged(sid,false)` alone reports a change against an *absent* baseline and fabricates phantom events. **An offline HOST is the case that retraction structurally cannot cover** — no journal event can be delivered at all, and `lastSessionsByHost` deliberately keeps serving that host's last good snapshot, so `JournalFreshness` re-asserts a frozen `busy: true` on every rebuild once the journal's word ages past the TTL; sessions read "Working" for as long as the host stays down, surviving cold launch via GRDB. The client retracts instead: `rebuildSessions` blanks `busy`/`prompt` for sessions on known-down hosts (`MultiHost.unreachableLiveSessionIds`), gated on `isNotKnownDown` (offline/noNetwork only) so a host inside its grace window doesn't flicker the list.
- **Sending to a tmux Claude session is `sendq.ts` driving `tmux send-keys` + screen-scrape confirm.** Two traps live here: (1) `send-keys -l` transmits text byte-for-byte, so an embedded `\n` is an Enter — multi-line messages submit/fragment at the first newline. Insert multi-line via bracketed paste (`load-buffer` + `paste-buffer -p`); Claude collapses it to a `[Pasted text +N lines]` chip and submits it whole. (2) Don't gate the Enter on re-finding your text in the composer scrape — a busy Claude swallows it into its own queue and clears the composer, so the scrape misfires. Confirm via transcript growth (idle) or composer-cleared → `queued` (busy). See `.claude/diagnosis-pending-pickup.md`. The full delivery trace (enqueue → hold → deliver → reconcile, one JSON line each) logs to **`~/.lfg/sendq.log`** — NOT `data/sendq.log`; `PATHS.data` is `~/.lfg`. Read it before re-deriving a "my message never arrived" report by live repro: the queue rows themselves are pruned (`KEEP_TERMINAL = 12`) but the trace is not.
- **The dirty tree IS other sessions' work — destructive ops have no undo here.** Never `git checkout --`/`git restore` a path that `git status` shows modified (one session did and destroyed another agent's uncommitted tests), and never `Write` to a path you haven't read this session — check existence first; "File updated successfully" in the tool result means it already existed and you just clobbered it (happened twice in one turn). To undo your own bad edit: `cp` the file aside first, or fix forward with Edit. Last-resort recovery: codex rollouts (`~/.codex/sessions/**/rollout-*.jsonl`, apply_patch diffs) and Claude transcripts are a real undo log for destroyed uncommitted work.
- **Concurrent sessions share more than files: test rigs and deploy trees too.** Multiple lfg agents may touch the same high-traffic files (stores, central views like `SessionStore.swift`) simultaneously → "file modified since read" errors and build breaks from someone else's in-flight code. Before editing a shared file, check `lfg-sessions` / `git status` for concurrent work and keep edits minimal and additive. Before LIVE verification, check no other agent is driving the same simulator/worktree/scratch server (two sessions once raced one sim for an hour, contaminating all evidence). Before archiving/deploying, snapshot the tree (worktree or stash) — never archive a tree another agent is mid-refactor in.
- **Machine identity is not session-constant.** A conversation can migrate hosts (Air↔Pro) mid-session; pids, sim UDIDs, and paths from earlier turns are then stale. Re-verify `hostname` before ANY machine-state op (kill, config write, deploy). Before restarting a REMOTE host's lfg server, confirm a second exec path onto that machine first (see memory [[air-ssh-access]]) — killing its server with no way back wedges the host until a human intervenes. "Done" for multi-host work includes `git push` + probing the OTHER host's live behavior.
- **Bun auto-loads `.env`.** `ps eww` does not show a Bun process's effective env — `cat .env` before reconstructing what a running server sees.
- **A server restarted over ssh loses `tmux`, and nothing says so.** `src/tmux.ts` spawns bare `"tmux"` inside try/catch, so when `/opt/homebrew/bin` is missing from the server's PATH — exactly what a non-interactive `ssh host 'cmd'` restart gives you (`PATH=/usr/bin:/bin:/usr/sbin:/sbin`) — every session on that host reports `tmuxTarget: null` and send/resume/spawn fail, while the host stays green in every client. In the desktop app those rows go grey and unopenable (`canOpen == tmuxName != nil`), which reads as a client bug. `scripts/serve-forever.sh` now prepends Homebrew itself and warns when tmux is unresolvable; if the symptom reappears, check the *launch env* (`ps eww <pid> | tr ' ' '\n' | grep ^PATH=`) before touching client code.
- **codex delegation inside a claude tmux pane breaks that session's send path.** The codex child makes two session rows claim one pane; the pane-collision guard nulls `tmuxTarget` and sends 409. Fingerprint: `tmuxName` set but `tmuxTarget: null`.
- **No bare `setInterval` fan-out over a collection** on the single Bun event loop — a growing collection turns the tick into a spawn storm. Batch or stagger.
- **Restarting a port-bound service:** kill by PORT, not by pkill pattern (stale processes silently keep the port), and verify the NEW code answers (probe a changed endpoint) before declaring the deploy done. **The `-sTCP:LISTEN` filter is not optional**: bare `lsof -ti :8766` also returns every *client* holding a connection — the `lfg` CLI, the desktop app, the phone — so it hands you a multi-PID list that either kills Eugene's apps or fails outright. Use `lsof -nP -iTCP:8766 -sTCP:LISTEN -t`.
- **`GET /api/file?path=…` is how the iOS client fetches host files for inline rendering** (`src/commands/serve.ts`). It's read-only and traversal-hardened via `realpath` containment against a fixed root set: `REPOS_ROOT`, `SELF_REPO`, `~/` (homedir), and `$TMPDIR/lfg-uploads`. A path resolving outside all of these → 403; missing → 404. Don't narrow these roots without checking what the client references (agents emit absolute paths under home/cwd — see the "Referencing files…" directive in the global `~/.claude/CLAUDE.md`). The endpoint's security posture is "same as the rest of the API" — the server itself is unauthenticated on 127.0.0.1; **client access is Cloudflare tunnel + Access** (`lfg-pro.eugenechantk.me`, config `~/.cloudflared/lfg-pro.yml`; unauthenticated requests 403 at the edge). Tailscale is DEPRECATED for client access (2026-08-22) — a phone/iPad "offline" on the tailnet is expected, and client connectivity problems should be diagnosed on the Cloudflare path (tunnel process, cold-connection timeouts, Access tokens), not the tailnet.

## iOS / Swift gotchas

- **`ios/` is the iOS client.** Build/install with FlowDeck (`/flowdeck`), never raw `xcodebuild`/`simctl`/`devicectl`.
- **Device-only iOS bug? First ask: did the device get the latest build?** A stale installed build (works on sim, broken on device) caused a file-open 404 that looked like a code bug.
- **SSE parsing:** `URLSession.AsyncBytes.lines` drops SSE blank lines — split raw bytes on `\n` yourself. `\r\n` is a single Swift grapheme, so `firstIndex(of: "\n")` never matches CRLF; split on `unicodeScalars` instead.
- **Seeding sim app state via plist: the full recipe, or it silently evaporates.** Don't drive SwiftUI text fields for URLs — but a bare plist write (PlistBuddy/`defaults write`) reports success and then vanishes, because **cfprefsd** holds a stale cache. Working sequence: (1) terminate the app, (2) write the plist directly (plistlib/PlistBuddy) in the sim data container, (3) `simctl spawn <udid> killall -9 cfprefsd`, (4) launch with `simctl launch` — NOT `flowdeck run`, which reinstalls and wipes the prefs. Prefer driving a real onboarding UI when one exists.
- **More sim/verification traps (each cost a session real time):** a pending notification-permission prompt persists in `usernotificationsd` across reinstalls (only `simctl erase` clears it); nav-bar toolbar buttons don't respond to synthetic taps — use raw HID `touch down`/`up`; FlowDeck's synthetic `pinch` doesn't drive `UIScrollView` zoom — `double-tap` is the deterministic proxy; `log stream` needs `--level info` or .info lines silently vanish; `simctl push` cannot wake background `didReceiveRemoteNotification` — verify background-only push paths on a device; device failure → pull the `.ips` crash log FIRST; never mutate navigation state synchronously inside UIKit's launch transaction (defer via `Task { @MainActor }`).

## macOS desktop app (`desktop/`) + macOS UI automation

- **Drive Apple UIs through the accessibility tree, not coordinates.** `cliclick` at correct coordinates silently fails on SwiftUI List row buttons (AXPress via System Events fires them first try), its `t:` typing is dead (use System Events `keystroke`), and the first click on an unfocused window only focuses it (activate + sleep first). **Never** send coordinate clicks at a security/TCC dialog — a miss can register as DENY and poison TCC.db for that app+service.
- **AppleScript from Swift:** `NSAppleScript` is main-thread-only AND blocks on the consent prompt — spawn `/usr/bin/osascript` via `Process` instead (see `Opener` in `desktop/LFGSessions.swift`).
- **iTerm windows that must run a command:** use `create window with default profile command "..."` — create-then-`write text` races zsh startup and the text gets swallowed. The command param is tokenized by iTerm itself: quoted args work, shell builtins (`exec`) don't.
- **A macOS toolbar costs ~300pt before the first item, and the display is usually asleep.** Window width minus ~300 is the budget every toolbar item shares; over it, items silently fall into the » overflow (that's why `desktop/`'s min width was 760 for a full-size toolbar and 440 for the compact one). A *centered* (`.principal`) item is the worst offender — it reserves twice the wider side. Don't derive these numbers by eye: `lfg --window-fit <widths…>` builds the real window off-screen and reports items vs `visibleItems`, and `--window-shot <width> <png>` draws it (chrome included) via `cacheDisplay`. Both work with the login session locked — which it normally is, since sessions are driven remotely. Take a throwaway `screencapture -x` before *any* GUI automation here: a black frame means stop and go headless, and it's one call versus the six AX dead-ends it replaces.
- **Ad-hoc codesigning makes TCC grants per-build** (each rebuild re-prompts or silently denies automation). Sign with the keychain Developer ID for a stable TCC identity.
