## The model

A **Space** is an isolated Linux desktop. **Codex** works inside it. These are two different things with two different controls, and the whole design hangs off keeping them apart:

| | Controlled by | Lives in |
|---|---|---|
| The agent | Stop / Send in the composer, Take control | the chat and the stage |
| The Space | Start / Stop this Space | the Space sheet, one tap away |

Taking control **pauses the agent only**. The desktop, its apps and its downloads keep running. Sending another chat message hands control back to Codex — that is the only resume, and the handoff board says so on screen.

## Flow

Message → pick or create a Space → chat → the desktop strip above the composer → **Watch** → **Take control** → full screen → **Done** → back to watching, phone back in portrait.

## The one new component: the stage

The phone cannot hold a transcript and a live desktop at full size at once. A Chat/Desktop tab pair would hide one to show the other, which defeats the point — you watch *because* you are reading the chat.

So the desktop takes the slot S2 already reserves for its pill row, in two states:

- **Resting, 44pt.** A live thumbnail, "Desktop", the agent's one-line status, and **Watch**. Always visible, costs the transcript nothing it was using.
- **Watching, 229pt.** A 366×229 player with an overlay bar: status dot, what the agent is doing, and **Take control**. The transcript gives up 185pt and the composer never moves.

Tapping the chevron collapses it again. That is the whole chat↔desktop story on the phone.

## Status language

Five Space states, each a dot colour reused from S2, plus one mode that is deliberately *not* a status:

| State | Dot | Row line |
|---|---|---|
| Needs input | amber `#FF9F0A` | "Asks: send this reply?" |
| Working | green `#30D158` + halo | "Working · writing a draft · 3m" |
| Ready | blue `#0A84FF` | "Ready · desktop is running" |
| Stopped | grey `#636366` | "Stopped · send a message to start it" |
| Host offline | hollow amber ring, row at 50% | "Air is offline · last seen 14m ago" |

**Controlling is a mode.** It gets no sixth colour. It gets a 3pt `#0A84FF` ring around the whole screen and a blue "You have control" chip beside an amber "Agent paused" chip. Watching has neither, so the two read apart even in a thumbnail.

## Copy rules

- **Nothing is sent until it is confirmed.** The agent writes a draft and says "nothing has been sent". The ask panel shows the real recipient, subject and body; the footnote repeats it; the second button is **Keep it as a draft**, not Cancel.
- **No implementation jargon.** "Let this Space read a folder?" with the folder name, the host and "read-only". No mounts, no containers, no bind paths.
- **Accounts are facts, not settings.** "Google · connected — signed in inside this Space" is a plain row in the transcript, the same shape as a shared folder.

## Gestures in manual control

One finger is the guest; two fingers are your local view. That split is the whole model.

| Gesture | Does |
|---|---|
| One finger, tap or drag | the guest cursor — tap, drag, select |
| Two-finger tap | right-click |
| Two fingers, drag | pan the local viewport (never reaches the desktop) |
| Pinch | zoom, 1× to 4×; the factor shows beside Fit past 1× |
| **Fit** | whole desktop, centred, back to 1× |

Chrome is Done, Fit and Keyboard, nothing else. Portrait fits to width (390×244) and says to turn the phone; landscape fits to height (624×390). Landscape-right is landscape-left mirrored — the chrome insets on whichever side the sensor housing is. The keyboard row carries what a Linux desktop needs and iOS will not send: esc, tab, ctrl, alt, arrows, return. The hint strip fades a few seconds after you enter control; the boards draw it visible so the mapping is reviewable.

## Decisions worth arguing with

1. **Message is a third tab, not a mode of Sessions.** Spaces have their own lifecycle (power, desktop, shared folders) that a session row has no place for.
2. **Mac wide shows chat and desktop together; narrow does not.** The 400pt window gets the phone's stage strip instead, because 400pt cannot hold a legible 16:10 desktop and a transcript.
3. **Codex is the only agent that drives the desktop.** Claude Code is offered in the create sheet but the note says plainly that it works over the terminal and does not drive the screen.
4. **Dark only**, like every S2 and iPad board on this canvas. A light pass belongs with the Sessions light pass, not alone here.

## Limitations

- The boards are web mock-ups of native controls. Build with native sheets, `UIScrollView` zoom and a real remote-desktop view; do not match pixel for pixel.
- The desktop render is a drawn stand-in for a live frame. It is there to show scale, chrome and legibility, not pixel fidelity.
- Not drawn as separate boards: iPad portrait, the Mac light appearance, Dynamic Type wrapping, and the first-run gesture overlay. The notes cover the rules.
- Sheet and stage heights come from the boards, not from a built screen. Measure before fixing any detent.
