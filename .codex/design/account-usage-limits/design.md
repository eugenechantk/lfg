# Usage limits: design

A proposal for review. No product code changed.

- **Canvas:** LFG UI Map, https://claude.ai/artifact/F2B1MNbv5oxuscm237M9sD
- **Version:** `1792476940-c745` (Version 87), published 2026-10-20. Page **Usage limits (Oct 20)**, id `usage-limits`, 14 boards prefixed `usage-`, 5 notes prefixed `usage`. The other 163 boards, 8 pages and 64 notes were read back unchanged.
- **Exact sources:** `reference/project/*.dc.html`, generated by `reference/gen_boards.py` from `reference/scenarios.js`. Board frames and notes: `reference/canvas-entries.json`.
- **Standalone preview:** `preview/index.html` — the same six scenarios, with theme and scenario controls.
- **Data contract:** `.codex/brainstorm/account-usage-limits.md`.

Every value, plan name and account label in the boards and the preview is a **sample**. "Now" is fixed at Tuesday, Oct 20 2026, 2:58 PM Hong Kong time. No real credential or address is quoted.

## Direction

**One sheet, one card per account, one refresh.** It reuses the retry-later sheet's shape, the S2 list's colours and the grouped-form card, so it adds no new visual system. Three decisions carry it:

1. **Group by account, not by host.** A provider heading, then one card per account. Hosts are a line inside the card. The same sign-in on Pro and Air is one quota, so it is one card.
2. **Name a window by the duration the provider reported** — "Current window · 5 h", "Weekly · 7 days" — never by the API's key name. A window that was not reported is said so, and draws no bar.
3. **Every card carries its provenance**: when the reading was taken and from where. A reading with no age is a reading you cannot judge.

The quotas belong to the account and span every conversation on it. This is not context-window fullness and not token spend for one session; the sheet's footnote says so.

## Menu placement

A plain row in the session list ••• menu (`moreMenu`, `SessionListView.swift:869`), in the **first section, between Terminal and Settings** — with the other read-only destinations, above the GROUP BY and SORT BY sections. Icon `gauge.with.needle`, identifier `sessions_usage_limits`. The desktop host-strip menu (`SessionsListS2.swift:171`) gets the same row.

Not the list header: the header says which hosts are up, and a percentage there competes with what the list is scanned for. Not Settings: nothing here is a setting. Not a tab: two tabs already carry badges, and a third destination is too much furniture for a number checked a few times a day.

## Presentation

| Platform | Presentation | Size |
|---|---|---|
| iPhone | `.sheet`, fitted height detent, `.large` as a second detent | ~700pt in the normal state; 34pt bottom inset |
| iPad | Form sheet, `.presentationSizing(.fitted)` | 460pt wide, content height, capped at ~754pt then scrolls |
| Mac | **Popover** anchored to the host-strip ••• button | 320pt wide, ~430pt tall, capped at 520pt then scrolls |

The Mac gets a popover rather than a sheet, which is where this parts company with Retry later. Retry later is a task with a commit step, so a modal earns its cost. This has no commit step — it is a glance — so a popover that dismisses on an outside click is the cheaper, more correct control. `Esc` closes it; `⌘R` refreshes.

## Sheet anatomy (phone, 390pt)

Top to bottom, 20pt side inset throughout:

1. **Grabber**, from `.presentationDragIndicator(.visible)`.
2. **Header, 48pt.** **Close** on the leading side (17pt, accent), "Usage limits" centred (17 semibold), **Refresh** trailing (17pt, accent). The leading action is Close, not Done: the screen saves nothing, and Apple places Close and Cancel leading with Done reserved for a trailing commit.
3. **Provider heading** — "CLAUDE CODE", "CODEX". 13pt semibold, uppercase, 0.04em tracking, `tertiaryLabel`. 22pt above, 8pt below.
4. **Account card.** Radius 20, `tertiarySystemGroupedBackground` on a `secondarySystemGroupedBackground` sheet — the same pairing the retry-later sheet uses.
   - **Identity row, ~58pt.** Plan at 17 semibold ("Max 20×", "ChatGPT Pro", "API key"). Below it, 13pt grey: the account label and the hosts it covers.
   - **Quota row, ~83pt**, with a hairline above. Label and percentage share one baseline (16pt; the percentage semibold and tabular). Then a 6pt capacity bar, radius 3, over a track at label-ink 16%. Then the reset line at 13pt.
   - **Notice block** replaces the rows when there is nothing to plot: 16pt semibold title, 13pt grey body, and an optional 34pt action button.
   - **Card note**, 13pt grey, only when identity is unproven.
   - **Footer, 34pt.** 12pt. When the reading was taken and from where.
5. **Footnote**: a SAMPLE tag plus "Quotas belong to the account, not to one session."

iPad uses the same metrics. The Mac drops to 13 / 12 / 11 / 10pt, 12pt padding, radius 12, and a 5pt bar.

## Account grouping and identity

This is where the design can most easily lie, so the rule is explicit.

- Two hosts collapse into **one card** only when both **identify the same account**. The footer then reads "Shared across Pro and Air".
- Different sign-ins → **separate cards** under the same provider heading, each labelled with its host.
- A host that **does not identify its account** gets its own card titled by host ("Air · account not identified") and a note: "Air didn't identify its account, so it is shown on its own. It may be the same account as Pro." Never merged on a guess, and never silently split without saying why.
- A card whose plan is unknown says "Plan not reported" rather than inventing one.

## Quota rows, labels and reset copy

Each window is classified by its own reported duration, so a provider that adds a third bucket appears with no code change. `primary` is not a promise of five hours.

| Label | From |
|---|---|
| "Current window · 5 h" | Codex `windowDurationMins` 300, or Claude `rate_limits.five_hour` |
| "Weekly · 7 days" | Codex `windowDurationMins` 10080, or Claude `rate_limits.seven_day` |

Reset copy stays one short line and names the clock time first, because that is what gets acted on:

- Today: "Resets 4:10 PM · in 1 h 12 m"
- Another day: "Resets Sat, Oct 24 · in 4 d"
- Exhausted: "Used up · back at 4:10 PM, in 1 h 12 m"
- Reset passed while a host was offline: "Reset 2:40 PM — may already have rolled over"

## Warning thresholds

| Used | Bar and value | Copy | Why |
|---|---|---|---|
| 0–74% | Accent blue | Plain reset line | Information, not a warning |
| 75–89% | Amber | Unchanged | Attention without alarm — the same amber the list uses for needs-input |
| 90–99% | Amber | "Little left · resets …" | A word, so colour is never the only carrier |
| 100% | Red, full | "Used up · back at …" | The reset time becomes the headline; it is the only thing left to act on |
| Not reported | **No bar** | "Not reported" | A zero-length bar reads as 0% used |

Tone is derived from the number in one place (`tone(p)` in the boards), never hand-set per row. Blue, amber and red differ in lightness as well as hue.

## Empty, error and stale states

**A missing window is never 0%.** The live Codex login returned a weekly window and nothing else, and that shape has to survive the design. Such a row reads "Not reported" in grey with no bar and no track — an empty track reads as "nothing used", which is a lie in the most expensive direction.

**No observation yet (Claude).** Claude reports limits only with an API response. The card shows a quiet notice — "No reading yet · Claude reports limits with its next reply on this account" — not 0%, not an error, and not a prompt to sign in.

**A failed read is not a signed-out account.** The notice names the host in plain words: "LFG couldn't reach Air for an update. This does not mean the account is signed out." No status codes in the UI. The last good reading and its age stay in the body, and a **Try again** button sits in the card. Sign-in copy appears only when the provider itself says the credential was rejected.

**Stale.** The footer turns amber and says how old the reading is. The **numbers are never dimmed** — a stale reading is still the best information there is, and dimming it just makes it hard to read.

**Offline host.** The card stays at 58% opacity rather than disappearing, so an account does not silently lose a window. The footer says "Air is offline — last read 14 min ago".

**API billing.** An API-key account shows a short explanation and no bars. There is no subscription window, so none is invented.

## Refresh

One action, in the header. Opening the sheet refreshes every host, with a short cache so a reopen does not hammer them. While a refresh runs the header reads "Refreshing" with a small spinner and is disabled, card footers read "Refreshing…", and **the numbers stay on screen**. Nothing is blanked and nothing is replaced by a spinner.

A per-card **Try again** appears only in the error state. There is no per-card refresh otherwise: with at most four cards, two taps for one job is noise.

## Accessibility and keyboard

- Each quota row is **one combined element**: "Claude Code, Max 20×, current window, 5 hours, 62 percent used, resets in 1 hour 12 minutes."
- The bar is hidden from VoiceOver. Apple's gauge guidance asks the label to name the value and both ends of the range; the row text already does, and a gauge that repeats it double-speaks.
- Every warning state carries a word as well as a colour.
- Dynamic Type scales the text. The bar stays 6pt and the row wraps to two lines at accessibility sizes.
- Targets are at least 44pt on the phone, Try again included.
- `Esc` closes; `⌘R` refreshes on iPad and Mac. Tab order: Close → Refresh → each Try again in card order. Focus returns to the menu button on close.
- Suggested identifiers: `sessions_usage_limits`, `usage_sheet`, `usage_refresh`, `usage_card_<provider>_<n>`, `usage_row_<window>`, `usage_retry_<host>`, `usage_dismiss`.

## Material tradeoffs

- **Popover on Mac, sheet on phone.** Consistency with Retry later would have argued for a sheet everywhere. A sheet buys a commit step this screen does not have, and costs a dismissal gesture on every glance. The inconsistency is deliberate and small: the content inside is identical.
- **One refresh, not per-card.** A per-card refresh is more precise and more honest about what failed. With at most four cards it is also four controls doing one job, so Try again is kept for the only case that needs it.
- **Bars at all.** Percentages alone would be lighter and perfectly readable. The bar earns its 6pt because the common use is a glance across four windows, and relative length is read faster than four numbers.
- **The age is in the footer, not beside each number.** Per-row ages would be more precise, but every window on one card comes from one read, so the repetition would be noise.
- **No history.** A sparkline or a burn rate would answer "am I going to run out today", which is a better question than the one this screen answers. It needs data nobody is collecting yet, so it stays out rather than arriving as an estimate.

## Limitations

- The boards are web mock-ups of native controls. Build with native `.sheet`, `NSPopover` and `Gauge`/a plain capsule; do not match the boards pixel for pixel.
- Sheet heights are measured from the boards, not from a built screen. Measure the real content height before fixing the detent.
- Light values are derived from the system colours the tokens render, not separately designed — the same rule as decision D6 in `.claude/feature/sessions-redesign-s2.md`.
- Account labels, plan names and every percentage are samples. The only shape taken from a live response is Codex returning a weekly window and no short window; its values here are invented too.
- Not drawn as separate boards: the Mac light error state, the iPad portrait layout, and the Dynamic Type wrap. The rules above cover them.
