### 2026-08-25 — Desktop refresh() is window-driven; locked-screen stub harness sees only /api/info

**What happened:** To verify the desktop client sends `exclude` params, I launched a second
app instance against a request-recording stub host with a scratch `LFG_DESKTOP_CONFIG_DIR`.
Two runs (8s and 25s) recorded only `/api/info` — the lightweight reachability ping. The full
`refresh()` (sessions + resumable fetch) never fired because the login session was locked and
the window/scene that drives the refresh loop never appeared.
**Why this was inefficient:** Two 25s app-launch cycles spent before recognizing the pattern.
The repo memory (`desktop-window-shot-renders-fixtures`) already hinted that only purpose-built
off-screen harnesses work while locked.
**What better looks like:** For locked-screen desktop verification, don't try to drive the live
app's network loop. Split the seam instead: (1) compile the exact URL-construction code as a
10-line `swift` script to get the byte-for-byte request URL, (2) curl that URL against the real
server. That closed the loop in under a minute and is deterministic.

### 2026-08-25 — Wrong reachability conclusion and wrong deploy-path assumption for the Air

**What happened:** I tried `ssh eugenechan@eugenes-macbook-air` (timed out) and `tailscale ping`
(offline), then told Eugene the Air was unreachable and that deploying needed a git push plus a
risky API-driven restart. Eugene corrected me: the `air` alias works. It did — and the Air's
working tree already contained my edits byte-for-byte via Syncthing, so no push was needed at all.
**Why this was wrong:** The desktop `hosts.json` I had ALREADY read this session says
`"ssh":"air"` — the exec path was named in data on my screen. And the memory
`claude-folder-sync-dead` / repo hazards note Syncthing syncs across hosts; I never checked
whether the repo itself syncs before declaring a push mandatory.
**What better looks like:** Before declaring a host unreachable, try every configured access
path — especially aliases named in the very config being debugged (`ssh air`, not just the raw
hostname). Before designing a code-transfer step, check whether the target already has the
bytes (hash the files remotely). Saved: the whole commit-permission blocker was imaginary.
