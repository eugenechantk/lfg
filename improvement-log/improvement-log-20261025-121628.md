### 2026-10-25 — `git apply --unidiff-zero` misplaced a pure insertion

**What happened:** To split shared files across commits I staged a subset of `git diff -U0` hunks with `git apply --cached --unidiff-zero`. A pure-insertion hunk (`@@ -3557,0 +3595,6 @@`) landed 30 lines too low, inside an expression, because earlier hunks of the subset were skipped. I committed it, saw the stray `-6/+6` hunk on the next listing, and amended.
**Why this was wrong:** With zero context, git apply has nothing to anchor on; a subset patch's insertion positions are not reliable. I trusted a staging method without checking its output before committing.
**What better looks like:** Rebuild the file from the index blob by OLD line numbers, write it with `hash-object -w` + `update-index --cacheinfo`, and assert each hunk's minus lines match (the scratchpad `hunks.py` now does this). Always run a typecheck on `git write-tree` of the index before each commit; it would have caught this.

### 2026-10-25 — session-cleanup ignores repo visibility and evidence size

**What happened:** The skill says to commit the whole dirty tree. The lfg repo is public on GitHub, and the tree held 1.26 GB of untracked evidence: screen recordings, Instruments traces, a copied FlowDeck binary, a built desktop app, raw Claude transcripts, and per-run reports of the TikTok/iPhone automation runs.

Consider .gitignore rules for `.codex/**/*.mov`, `**/*.trace/`, `.codex/feature/**/tooling/`, `.codex/feature/**/desktop-build/`.
