## Log

### 2026-08-08 — Duplicated an entire investigation with a parallel session

**What happened:** Eugene sent the same two-bug prompt to two sessions (861f8163 and me,
d7922615). I investigated both bugs from scratch, wrote a full diagnosis artifact, and was
about to edit `src/sessions.ts` when `git status` revealed the other session had *already
written* the complete fix — including the same root cause, the same winner-selection design,
and defense-in-depth in the push watcher I hadn't gotten to yet.

**Why this was wrong:** The signal was in my fourth tool call. My own `/api/sessions` dump
printed two rows titled `Two things 1. There is a session that ke…` — my session and the
other one, same prompt, both busy. I was scanning that output for duplicate *session ids*
(the bug) and never registered the duplicate *titles* (the coordination hazard) in the same
table. I found the thing I was looking for and stopped looking.

**Cost:** ~15 tool calls of redundant investigation, and a near-miss on concurrent edits to
three shared files (`src/sessions.ts`, `src/push/watcher.ts`, `ios/LFG/SessionStore.swift` —
the last already carrying a *third* party's in-flight nav-alias changes). Two agents writing
`sessions.ts` simultaneously is exactly the failure `.claude/CLAUDE.md` warns about.

**What better looks like:** When a task starts with a session listing for any reason, scan it
for *my own prompt* before scanning it for the bug. Concretely: the very first thing to do in
an lfg debugging task is `curl /api/sessions | grep` for my own title/lastUserText — if
another live session shares it, resolve ownership *before* investigating, not before editing.
A one-line check that saves an entire redundant investigation.

### 2026-08-08 — Concurrency check ran at edit time, not at task time

**What happened:** `.claude/CLAUDE.md` says "Before editing a shared file, check
`lfg-sessions` / `git status` for concurrent work." I followed that literally — I ran
`git status` on the exact files I was about to modify, immediately before modifying them.
That is what caught the collision, so the rule worked. But it fired after all the
investigation was already sunk.

**Why this is worth fixing:** The rule is written to protect *file integrity*, and at that it
succeeded. It does nothing to protect *effort*, because by the time you're editing you've
already done the thinking. The expensive part of an agent session is usually the
investigation, not the edit.

**What better looks like:** Split the check in two. Keep the existing pre-edit `git status`
guard for file safety, and add a pre-*investigation* ownership check for effort: on any lfg
task, resolve "is another live session already on this exact request?" as step zero. Worth
proposing as a project CLAUDE.md amendment — the current wording actively suggests the late
check is sufficient.
