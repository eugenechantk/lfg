## Log

### 2026-10-08 — A bundled model list used as a validity gate silently erased every newer model

**What happened:** The new-session sheet copies the model of the newest session in the chosen directory. Both iOS (`AgentModelSelection.inferred` → `restoring`) and desktop (`restoredSelection`) checked that model against the app's hardcoded list (iOS stops at gpt-5.6, desktop at gpt-6-astra). gpt-6.1-sol was not on it, so it became the bundled default. A unit test ("SC6") pinned this behaviour as intended. The send path had the same trap: it reconciled against the bundled fallback whenever the host's live catalog had not been loaded.
**Why this was wrong:** The server stopped allowlisting models long ago (it only checks the id grammar), and the live catalog is the real authority. A bundled list is a floor for old hosts, and any check against it decays every time a provider ships a model.
**What better looks like:** Treat a model id as valid if it is syntactically safe, and reconcile only against the selected host's live catalog, at the request boundary (see [[enforce-at-the-boundary]]). Grep for other `.contains(model)` checks against bundled lists before the next model launch.

### 2026-10-08 — Passed `-S "$U"` to flowdeck despite the memory

**What happened:** Put the simulator UDID in a shell variable to shorten four flowdeck calls. The guard hook blocked the whole command, which memory [[flowdeck-sim-guard-cwd]] already warns about.
**What better looks like:** Always paste the literal UDID. The memory exists; the miss was not re-reading it before a compound command.

### 2026-10-08 — First plan rewrote the compiled model list

### 2026-10-08 — Read the sim's prefs plist too soon after a write

**What happened:** After a foreground, the plist still showed the old `fetchedAt` 6 s later, and I started to suspect the refresh. Four seconds later it showed the new time. cfprefsd writes the file to disk late.
**What better looks like:** When proving a UserDefaults write from the sim's plist, poll for up to ~15 s, or read the app's own log first. "Not on disk yet" is not "not written".
