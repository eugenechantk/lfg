## Log

### 2026-10-15 — A `--help` probe provisioned a simulator and evicted a peer's sims

**What happened:** I ran `flowdeck ui simulator session --help` to read the CLI help. The guard matched `flowdeck` + `ui`, found no `-S`, provisioned `cc-59836304`, and admission control shut down two sims of session 68284ba9 (idle 10-11 min).
**Why this was wrong:** Two faults. Mine: I knew the guard intercepts `flowdeck ... ui` and still ran a guarded command to read help. The guard's: `--help`/`-h` never touches a simulator, but it is not exempt, so a help read has real side effects on other sessions.
**What better looks like:** Read flowdeck help through `flowdeck help ui` style paths or the skill docs, or exempt `--help`/`-h` in `guarded_segment_targets_sim`.

### 2026-10-15 — Guard ignored `(flowdeck …)` / `time (flowdeck …)` — subshell parens hid the command from isolation

**What happened:** SC5 verification ran `time (flowdeck ui simulator screen -S …)`. The released sim was not rebooted and the command failed with "not booted". `guarded_segment_targets_sim` looked for an exact `flowdeck` token; shlex produced `(flowdeck`.
**Why this was wrong:** Any agent that wraps a FlowDeck command in a subshell bypassed per-session isolation, stamping and now the reboot — silently.
**What better looks like:** Fixed (paren-unwrapping + basename match + unit test). Lesson: parsers that gate safety need tests for the shell shapes agents actually type (`time`, subshells, absolute binary paths), not just the canonical form.

### 2026-10-15 — An internal Claude Code agent (agent_id, no agent_type) got its own simulator provisioned and never fires SubagentStop

**What happened:** During a haiku probe subagent run, payload.log shows a PreToolUse Bash from `agent_id a1d7dca0…` with no `agent_type`, not in any transcript. The guard provisioned and booted `cc-59836304-a1d7dca0` for it; the hook was apparently killed before stamping. No SubagentStop ever came.
**Why this matters:** Each such agent costs a booted sim (~1.3 GB) that ownership-scoped release would never free.
**What better looks like:** Main Stop with no subagent running now releases the whole namespace. Open question worth a look: should the guard refuse to PROVISION for an agent with no `agent_type` (map it to the parent's sim instead)?

### 2026-10-15 — Hand-piped Stop tests kept reporting "in use" because my own test shell named the sim

**What happened:** Three test runs were kept by the in-flight check — the Bash call piping the payload also contained the UDID or the `cc-<sid8>` name (in a `cat`, a python filter).
**Why this was wrong:** Cost three extra round-trips; the check was behaving correctly.
**What better looks like:** When testing a process-argv detector from inside the same process tree, build the identifying strings at runtime (`P="cc-5983""6304"`) so the test harness is not itself evidence.

### 2026-10-15 — Spent four real `codex exec` runs before finding that Codex silently skips untrusted hooks

**What happened:** The Codex Stop hook never ran. I tried the shell-wrapper theory, then the hook-group theory, then a wrapper script — one 1-minute codex run each — before grepping `config.toml` and finding `[hooks.state."…:stop:0:0"] trusted_hash`.
**Why this was wrong:** The lfg hook in the same event ran; the only difference was that mine was NEW. "New thing silently ignored" should have pointed at a trust/approval gate first.
**What better looks like:** When a newly registered hook never fires but an older sibling does, check for a trust/allowlist mechanism before changing the command. Saved as memory `codex-hooks-need-trust`.

### 2026-10-15 — The independent auditor found 5 real bugs after my own verification looked complete

**What happened:** My live tests all passed. The verification-auditor then found Codex UUIDv7 namespace collisions, a handoff shutdown already happening in production, a basename false-block, a race window and a hook-timeout overrun.
**Why it matters:** Self-verification tested the scenarios I designed for; the auditor attacked the design (id formats, concurrent sessions, timeouts).
**What better looks like:** Keep the auditor in the loop for any hook that runs in every session — it paid for itself several times over.
