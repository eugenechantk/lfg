## Log

### 2026-08-07 — Simulator screenshots omit AVKit playback controls

**What happened:** After tapping the inline video to reveal its transport controls, four consecutive
screenshots (both the UI-session `latest.jpg` and a one-off `flowdeck ui simulator screen`) showed the
video frames but *no* controls. I nearly concluded the controls weren't rendering — i.e. that the fix
had failed. Recording the screen (`flowdeck ui simulator record`) and extracting frames showed the full
control overlay, including the full-screen expand button, present the whole time.
**Why this matters:** AVKit renders playback controls out-of-process, and the screenshot path doesn't
composite that layer. A screenshot is therefore *evidence of absence that isn't* for anything AVKit
draws. Trusting it would have sent me back to re-fix working code.
**What better looks like:** For any AVKit/AVPlayerViewController surface (or any system remote-view UI:
share sheets, media pickers), verify with `flowdeck ui simulator record` + `ffmpeg -vf fps=1` frame
extraction, never a screenshot.

### 2026-08-07 — Synthetic taps don't fire AVKit control buttons

**What happened:** `flowdeck ui simulator tap -p 47,539` on the expand button did nothing across two
attempts (verified by recording — the player stayed inline). The identical coordinate via
`flowdeck ui simulator touch down 47,539` + `touch up` entered full screen immediately.
**Why this matters:** This is the same class of failure the project CLAUDE.md already documents for
SwiftUI nav-bar toolbar buttons ("use raw HID touch down/up"). It generalizes: any control not in the
in-process accessibility tree — AVKit controls don't appear there either — needs raw HID.
**What better looks like:** Rule of thumb — if an element is absent from `latest-tree.json` but visible
on screen, go straight to `touch down`/`touch up`; don't spend a round on `tap`.

### 2026-08-07 — Guessed FlowDeck swipe syntax

**What happened:** Used `flowdeck ui simulator swipe -p 200,300 --to 200,700` (invented) with stderr
suppressed, so three rounds of scrolling silently did nothing and I misread the stuck transcript as a
stalled SSE stream — a wrong hypothesis I started debugging.
**Why this was wrong:** FlowDeck's own rule 7 says don't invent syntax; `--examples` would have shown
`swipe down --distance 0.6` in one call. Suppressing stderr turned a loud error into a silent no-op.
**What better looks like:** Run `<command> --examples` before first use of any FlowDeck subcommand, and
never `>/dev/null 2>&1` a command whose success I haven't yet confirmed once.
