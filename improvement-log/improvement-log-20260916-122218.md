## Log

### 2026-09-16 — Test probes piped through `tail` reported tail's exit code and lost the summary

**What happened:** Ran `swift test | tail -40 > log; echo exit=$?` and `bun test | tail -30`. Both logs showed `exit=0` (tail's status) and the swift log held nothing else, so the run had to be repeated in full.
**Why this was wrong:** `$?` after a pipe is the last command's status. Piping a long test run into `tail` also throws away the output that would have shown a failure. Cost: one extra full swift+bun run.
**What better looks like:** Write the full output to a file (`cmd > log 2>&1; echo exit=$? >> log`) and grep the summary afterwards. Never pipe a verification command through `tail` before capturing its status.

### 2026-09-16 — Skipped session-cleanup step 0 (consolidate improvement logs)

**What happened:** The session-cleanup skill's step 0 runs `/consolidate-improvement-logs` first. The repo has 257 uncommitted log files; consolidating them rewrites memory/skills and would have delayed the build Eugene asked for.
**Why this matters:** The skill workflow assumes a normal end-of-session cleanup, not a "commit and ship now" request. The logs keep piling up because every cleanup skips this step for the same reason.
**What better looks like:** Run `/consolidate-improvement-logs` as its own session soon; consider making step 0 opt-in when the cleanup is invoked to unblock a deploy.

### 2026-09-16 — Exclude pathspec staged nothing and I moved on

**What happened:** `git add -- .claude/evidence ':!*.mov'` added no files (the exclude magic after `--` did not apply as intended), so `git commit` printed the status page and the evidence group was skipped. Two commits later the dirs were still untracked.
**Why this was wrong:** I printed `git diff --cached --stat` before every commit but did not check that it was non-empty. The `set -e` guard also did not stop the script because the failing command was inside a function called in a compound statement.
**What better looks like:** In a commit helper, fail loudly when nothing is staged (`git diff --cached --quiet && exit 1`). For exclusions, use `find ... ! -name` piped to `git add` rather than pathspec magic.

**What better looks like:** Bisect the hang (run `bun test` per file with `timeout 60`) in a separate session and fix or quarantine the file. Until then, cite the targeted set explicitly in any verification claim.
