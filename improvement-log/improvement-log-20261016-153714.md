### 2026-10-16 — "Brightest pixel" text-color check misread a resampled sim screenshot as pure white

**What happened:** To prove the new bubble text was #F2F2F7, I sampled the brightest pixel in the bubble from `flowdeck ui simulator screen` (402×874, downscaled from 3x). It read #FFFFFF, and I briefly suspected a caching bug in the text view.
**Why this was wrong:** The downscale filter overshoots on glyph edges, so the max pixel is brighter than the real color. The assistant prose (#F2F2F7 by design) showed the same overshoot (133 vs 138 pixels above #F2F2F7).
**What better looks like:** For text color, compare the dominant glyph colors against a control text with a known color on the same screen (or capture at full resolution with `record` + ffmpeg). Never use the max pixel. Worth a line in the flowdeck or design-verifier guidance.

### 2026-10-16 — A resumed background agent (SendMessage) is invisible in lfg

**What happened:** The design verifier finished its first pass blocked, and I resumed it with SendMessage. Eugene asked why lfg did not show it running.
**Why:** `parentLine` in `src/subagents.ts` handles the `async_launched` tool_result and `<task-notification>`, but not the resume result `{resumedAgentId}`. Its prefilter only lets through lines that contain `"agentId"`, so the resume line is skipped. The agent stays "completed" from its first notification.
**What better looks like:** Treat `resumedAgentId` as a new "running" lifecycle at that timestamp; the next task-notification completes it again. Until then, launch a fresh agent instead of resuming one when Eugene is watching in lfg.

### 2026-10-16 — Proposed an edge-case patch instead of fixing the status at its source

**What happened:** After finding that a SendMessage resume was invisible in lfg, I offered to "treat a resume as running again". Eugene: the fix should "accurately reflect the status of any child agent", not handle this edge case.
**Why this was wrong:** It was the third event-shape miss in the same parser (sync completion, async receipt, resume). Patching the next event keeps the design that produces these bugs. The child's own transcript already holds the true state.
**What better looks like:** For a wrong status, name the authoritative source first and derive from it; keep events as tie-breakers. Saved as feedback memory `fix-status-at-source-of-truth`.

### 2026-10-16 — First live probe missed the state under test

**What happened:** The first live resume test asked a haiku agent to `sleep 90`. A hook blocked the bare sleep, so it moved the command to the background and ended its turn after 8 s. My first poll came at +18 s (the scratch server answered slowly), so the test showed "completed" throughout and looked like a failure of the fix.
**Why this was wrong:** I did not make the state under test last longer than poll interval plus server latency, and I did not check the child transcript before reading the poll result.
**What better looks like:** Use a foreground command that hooks allow (`perl -e 'select(undef,undef,undef,75)'`) and read the child transcript's timeline next to the poll log. (The slip did expose the real background-wait case, which is now handled.)
