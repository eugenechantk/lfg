## Log

### 2026-09-15 — Stub host logged only 404s

**What happened:** The first stub-host script logged unknown paths and `close` only. When the stub session didn't show in the list, the log couldn't say whether `/api/sessions` had been hit; I had to patch and restart the stub mid-run.
**Why this was wrong:** A throwaway probe must log every request unconditionally — the whole point of the stub is observability. See memory `probe-shape-before-scripting`.
**What better looks like:** `log(method + path)` first thing in `fetch`, before routing. Bake it into a reusable stub template (`.claude/tools/stub-host.ts`) instead of rewriting it per session.

### 2026-09-15 — Foreground `sleep 150` blocked

**What happened:** Tried `sleep 150 && flowdeck ui simulator screen …` to wait for the offline promotion; the harness blocks long foreground sleeps.
**Why this was wrong:** Known rule: use `run_in_background` with an `until` loop or Monitor for waits.
**What better looks like:** For any wait > ~10s, start a background until-loop immediately and do parallel work (logs, docs) while it runs.

### 2026-09-15 — Stale code comment about resume minting a new session id

**What happened:** I based the first Decision Log entry ("orphan and live copy never share an id") on the comment in `src/commands/serve.ts` `resumeClosedSession`. The live seam showed the Pro's revived pane keeping `50980bea…`. Caught only because I read the new id back from `/api/sessions`.
**Why this matters:** The "one id, two processes" hazard from CLAUDE.md DOES apply for a bounded window after a forced transfer; the deferred close is what bounds it, and it must route by host id, not by session owner.
**What better looks like:** Treat code comments about agent CLI behaviour as claims to verify, not facts — one `curl` after the real action settles it. Fix the comment when touching that function next (not done this session: the comment block is shared with other in-flight edits to serve.ts).

### 2026-09-15 — Chased a transient banner with a slow screenshot

**What happened:** The transfer error banner lives 6s. `flowdeck ui simulator screen` takes 5–7s end to end, so three attempts (with and without `sleep`) all landed after it was gone and I briefly suspected the banner wasn't rendering.
**Why this was wrong:** I knew the banner lifetime from `StoreErrorEvent.lifetimeMs` before the second attempt; the tool's latency was the variable, not the app.
**What better looks like:** For any transient UI (<10s), start `flowdeck ui simulator session start --interval-ms 700` BEFORE the action, act, then grep `trees/*.json` for the text and pick the matching `screens/*.jpg`. Screenshots are for steady state only.

### 2026-09-15 — FlowDeck `session stop` deletes the capture directory

**What happened:** The first capture run found the banner in a tree frame, but `session stop` in the same command removed the directory before I copied anything; had to re-run the whole tap sequence.
**What better looks like:** `cp -R` the session dir to the scratchpad BEFORE `session stop`. Worth adding to the flowdeck skill notes / memory.

### 2026-09-15 — `??` with an async right-hand side does not compile

**What happened:** `switch preflight ?? (await transferPreflight(…))` → "'async' call in an autoclosure that does not support concurrency". Fixed with an explicit `if let … else { await … }`.
**What better looks like:** Swift 6 rule to remember: `??`, `&&`, `||` right-hand sides are autoclosures and cannot contain `await`.
