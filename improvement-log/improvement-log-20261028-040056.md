## Log

### 2026-10-28 — Usage limits shipped without 429 handling or persistence

**What happened:** The Claude usage card showed "No reading yet" on both hosts. The Anthropic usage endpoint returned 429 with a ~1 h retry-after. lfg's cache was in-memory, keyed by the rotating access token, with no negative caching, so restarts and rotations wiped the last reading.
**Why this was wrong:** The original feature was verified on a single live probe while the endpoint was healthy. The endpoint's budget is per account and Claude Code itself spends it (`?at_wall=1`, `?cedar_ember=1`), so 429 is the normal state under ~20 concurrent sessions, not an edge case.
**What better looks like:** For any third-party endpoint shared with other clients, design and test the 429 path (retry-after hold + last-known value on disk) before shipping. Verification should include "what does the user see when the provider says no".

### 2026-10-28 — Repeated the zsh `echo ====` mistake

**What happened:** A probe command used `echo ====` as a separator; zsh treats `=word` as path expansion and the whole compound command failed.
**Why this was wrong:** Memory [[zsh-bare-equals-word-aborts-command]] already documents it. I did not apply it.
**What better looks like:** Use `echo "----"` as the separator by habit.

### 2026-10-28 — ugrep alias fails on binary pattern search

**What happened:** `strings <bin> | grep -o '.{0,120}x.{0,200}'` hit ugrep's "exceeds complexity limits", and the retry with `/usr/bin/grep` took over 2 minutes on the 200 MB Claude binary.
**What better looks like:** Use `LC_ALL=C /usr/bin/grep -o` with short context windows, or `rg -a -o` directly on the binary.

### 2026-10-28 — The Air's server cannot read its Keychain

**What happened:** The Air's server (parent `serve-forever.sh` from a release dir, reparented to launchd) reported "Max 5×". Its Keychain says 20×; the fallback `~/.claude/.credentials.json` is a Syncthing-synced file that expired Oct 24.
**Why it matters:** Once the Air is back on a VPN, its Claude usage read will use the expired token and report "credentials rejected".
**What better looks like:** Start the Air server inside its GUI tmux server (as the desktop-app memory already says for signing), and consider ignoring `.credentials.json` when its `expiresAt` has passed.

### 2026-10-28 — Overclaimed the fix before the discriminating case ran

**What happened:** I told Eugene the Claude card "can't show No reading yet for an hour anymore". The fix only keeps a reading once lfg has one, and the 13:00 check showed lfg still can't win a call: the budget was gone 96 s after the reset.
**Why this was wrong:** Memory [[verify-the-discriminating-case]] applies. With no stored reading, the old and new builds show the same empty card. The claim depended on the 13:00 read I had not run yet.
**What better looks like:** Say what changes now (plan label, retry time) and what depends on a pending check, as separate sentences. Do not phrase a pending result as done.
