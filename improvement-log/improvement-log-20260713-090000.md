## Log

### 2026-07-13 — axdriver set-value doesn't drive SwiftUI TextField bindings

**What happened:** Verifying the desktop hosts settings pane, `set-value` on the `host_url_field` TextField set the AX value (readable back), but the SwiftUI `@State` binding never updated — the Add button stayed disabled and the subsequent press wrote nothing. Cost one wasted add/verify round-trip.
**Why this was wrong:** The macos-test skill already documents the escalation path (set-value → focus+type), but I treated set-value's success JSON as proof the binding took. AX value and SwiftUI state are separate for SwiftUI text fields.
**What better looks like:** For SwiftUI TextFields, after set-value immediately verify a *binding-driven* side effect (e.g. a dependent button's enabled state), not the AX value. If the side effect didn't fire, go straight to focus+type. Consider updating the skill: "set-value can succeed at the AX layer while the SwiftUI binding stays stale — check a dependent control."

### 2026-07-13 — axdriver type drops trailing keystrokes on longer strings

**What happened:** `type --text "http://bogus-host-test:8766"` (27 chars) landed only 20 chars ("http://bogus-host-te"). Typing the 7-char remainder completed it.
**Why this matters:** pid-targeted CGEvent typing is lossy at length; blind trust would have added a truncated host URL and produced a confusing verification failure.
**What better looks like:** After any `type` into a field, read the value back and top up the missing suffix before acting. For long strings prefer several short `type` calls. Worth adding to the macos-test skill's gotchas.

### 2026-07-13 — axdriver press returns success on disabled buttons

**What happened:** `press` on the disabled Add button returned `"pressed": true` (element JSON showed `"enabled": false`), while the app ignored the action — hosts.json unchanged.
**Why this matters:** The success flag reflects "AXPress was sent", not "the control acted". Trusting it skips a real verification.
**What better looks like:** Always check `enabled` in the returned element JSON before treating a press as effective, and verify the downstream state change (file content, new row) — which the skill already prescribes and which caught this.
