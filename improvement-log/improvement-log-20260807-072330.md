### 2026-08-07 — Assistant text before a question is hidden until answered (recurring) — FIXED

**What happened:** Eugene reported, again, that the response preceding a question is invisible in
the iOS client until the question is answered. Two independent root causes:

- **A:** Claude Code withholds the asking turn from its transcript until the question is answered,
  so the prose lives only on the tmux pane — and Claude runs in the alternate screen, so there is no
  scrollback. lfg spawned panes at tmux's default 80x24, which cannot hold a preamble plus a
  selector box, so the scrape returned a mid-sentence fragment or nothing.
- **B:** prompt state reached clients only as a journal *delta*, and a client's cursor starts at the
  journal head. `/api/sessions` had no `prompt` field at all, so a question asked before the client
  connected never surfaced — no panel whatsoever.

**Why it kept coming back:** every prior attempt treated it as one bug. Fixing the scrape alone
still left B; and even A's fix would have silently expired, because tmux does **not** restore
`default-size` after a client detaches — one Terminal-tab visit re-breaks it forever.

**What better looks like:** for a *recurring* bug, assume the earlier fix was correct-but-partial
and look for the second cause, plus the mechanism that lets the fix decay. Both were found here only
by driving the real client, not by reading code.

**Fixed in:** `src/tmux.ts` (pane geometry + `ensurePaneRows`, scan cap), `src/journal-pump.ts`
(reconcile on poll and on enumeration), `src/journal.ts` (`latestPrompt`), `src/commands/serve.ts`
(`prompt` on the session row), `ios/…/Models.swift` + `ios/LFG/SessionStore.swift` (baseline +
`promptStatedAt`). Docs: `.claude/diagnosis-question-preamble-invisible-20260807.md`,
`.claude/CLAUDE.md`. Memories: `live-question-prose-only-on-pane`,
`journal-delta-needs-rest-baseline`.

### 2026-08-07 — Retrospective journal analysis produced a confidently wrong conclusion

**What happened:** I correlated ~50 historical `prompt` events against preceding `msg` events and
concluded "the server side is clean — the text event is journaled 1s before the prompt, the client
has the data." That was wrong. Those `msg` events were the *answered* turns being flushed; I was
reading the aftermath, not the live state. A live repro (park a real session at a real question,
then hit the API) showed the transcript endpoint returning only the user message.

**Why this was wrong:** the transcript is append-only, so a retrospective read cannot distinguish
"written at time T" from "written later and stamped T". I had even measured the flush timing for a
Bash tool and generalised it to AskUserQuestion without checking — and interactive tools behave
differently.

**What better looks like:** for any "when did this become visible" question, the only valid evidence
is observing the live state. Park the system in the failing state and query it. This is the memory
`ground-truth-before-hypothesizing` applying to *timing*, not just errors.

### 2026-08-07 — A fix without a reconciler has an expiry date

**What happened:** the natural fix was "create panes bigger." Testing the attach/detach cycle showed
`before: h=60 → attach: h=23 → after detach: h=23` — tmux never restores the size. Had I shipped
creation-only sizing, the bug would have returned the next time Eugene opened the Terminal tab, and
looked exactly like "we never fixed it" for a third time.

**What better looks like:** when a fix sets a value on a resource that something else can also
write, always ask what else writes it and add reconciliation. Test the adversarial interaction
(attach/detach, restart, reconnect) *before* shipping, not after the regression report.

### 2026-08-07 — Fixed visibility but not placement; Eugene had to ask for the obvious presentation

**What happened:** I made the missing prose visible and shipped it rendered inside the "Needs your
input" card, because that is where the previous attempt had put it. Eugene immediately asked why it
wasn't just regular response text. It should have been — it's the model answering, and in the card
it read as a form caption in flat `.subheadline`, subordinate to the options it exists to explain.

**Why this was wrong:** I inherited the previous fix's framing ("context is a property of the
prompt") instead of asking what the text actually *is*. The bug report said the missing thing was
"the response" — Eugene's own words — and a response belongs in the transcript. I optimised for
restoring the data and never re-examined the container I was pouring it into.

**What better looks like:** when restoring something that was missing, ask where it belongs *now*,
not where the broken version put it. A repeat report is a signal that the earlier framing may be
part of the problem. Specifically: if the fix's output is user-facing, describe the intended
presentation in one line before implementing, so the placement decision is explicit rather than
inherited.

### 2026-08-07 — Killed the wrong process restarting the server

**What happened:** used `lsof -ti :8766` and killed the first PID, which was the lfg **desktop app**
(a client holding ESTABLISHED connections), not the server. The server kept running and I briefly
believed the restart had happened.

**What better looks like:** `lsof -nP -i :8766 | awk '/LISTEN/{print $2}'` — filter for LISTEN.
`-ti` returns every process with a socket on that port, clients included. The repo's CLAUDE.md says
"kill by PORT"; it should say "kill the LISTENER."

### 2026-08-07 — Rediscovered FlowDeck's CLI surface one error at a time

**What happened:** six failed invocations learning that it's `ui simulator screen` (not
`screenshot`), that `-p x,y` takes a comma pair (not `--x/--y`), that `type` takes a positional
argument (not `--text`), and that the sim guard reads literal argv so `-S "$VAR"` is rejected.

**What better looks like:** run `flowdeck help ui simulator <sub>` once up front for the subcommands
a task needs, instead of guessing flags. Worth adding the tap/type/screen/swipe invocation shapes to
the flowdeck skill or a memory if this recurs.
