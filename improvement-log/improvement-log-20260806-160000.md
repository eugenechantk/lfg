### 2026-08-06 — Guessed the send API route instead of reading it

**What happened:** Built a full 40-iteration polling repro against `POST /api/sessions/<id>/messages`, which returned `{"error":"not found"}` immediately. The real route is `/send`; `/messages` is GET-only. I had already grepped the route table and seen `/messages` as a GET, but reached for it anyway.
**Why this was wrong:** The memory [[probe-shape-before-scripting]] says exactly this: run the probe once and eyeball the real record before wrapping it in a loop. A sentinel output (`error: not found`) repeated 40 times is the tell that the probe itself is broken.
**What better looks like:** Before wrapping any endpoint in a poll loop, curl it once bare and read the response. One extra call, saves the whole loop.
