## Log

### 2026-08-29 — argv tokens masquerading as environment variables

**What happened:** Verifying what env a mosh session's shell sees, I ran `ps eww -o command= <pid> | tr ' ' '\n' | grep -E '^(TERM|COLORTERM)='` against the mosh-server pid rather than its session-shell child. mosh-server's own argv contains `-l LANG=en_US.UTF-8 -l COLORTERM=truecolor`, so the grep "found" COLORTERM and I briefly concluded the variable had been delivered. It had not — mosh-server drops every non-locale `-l`.
**Why this was wrong:** `ps eww` prints argv AND envp in one stream; a `KEY=VALUE` pattern match cannot tell them apart. Three rounds of probing went to disambiguating that.
**What better looks like:** When reading env from `ps eww`, print the WHOLE output once and eyeball where argv ends, or read env from inside the process (`printenv > file`) — which is what finally settled it in one shot. Extends [[probe-shape-before-scripting]].

### 2026-08-29 — an empty pid variable turned a probe into a host-wide dump

**What happened:** A `pgrep` returned nothing, `$sh` was empty, and `ps eww -o command= $sh` silently listed every process on Pro. The grep then returned ~150 mixed `TERM=xterm` / `TERM=xterm-256color` lines that looked like meaningful data.
**Why this was wrong:** No guard on the pid, and the output shape (many lines where one was expected) should have been an instant stop, not something to interpret.
**What better looks like:** Guard every derived pid (`[[ -n $p ]] || { echo "no pid"; exit 1 }`) before feeding it to `ps`/`kill`, and treat an unexpected line count as a broken probe.
