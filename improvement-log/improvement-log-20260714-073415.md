## Log

### 2026-07-14 — Proposed/applied the fix before disconfirming it (disconfirm-before-root-cause applies to FIXES too)

**What happened:** Correctly diagnosed the iOS full-banner disconnects as the Pro Mac sleeping and freezing the Bun server. But I then launched a detached `caffeinate -is` stopgap and framed it as the fix — without first checking (a) that MacCommandCenter.app was ALREADY running a continuous `caffeinate -i -s` (so idle sleep was already handled), and (b) that the sleeps actually hitting were `Clamshell Sleep` (lid-close), which `caffeinate` physically cannot prevent. Eugene pushed back ("MacCommandCenter is already caffeinating, no?"), which forced the check that revealed my stopgap was redundant and didn't address the real cause. The real fix is `sudo pmset disablesleep 1`.
**Why this was wrong:** The memory [[disconfirm-before-declaring-root-cause]] says to name the check that would prove a theory innocent and run it BEFORE writing the diagnosis. I applied it to the diagnosis (ran pmset logs, ruled out crashes/PTY) but NOT to the proposed fix. "Add a caffeinate" had an obvious disconfirming check — "is something already caffeinating, and does caffeinate even cover the sleep type in the logs?" — that I skipped in the rush to ship a stopgap while Eugene was away.
**What better looks like:** Before applying a fix (not just before declaring a cause), state the check that would show the fix is insufficient/redundant and run it. Here: `pgrep caffeinate` (already covered?) + `pmset -g log | grep Entering | grep -oE "'[^']+'"` (what sleep type — is it one caffeinate can't stop?). 30 seconds, would have gone straight to `disablesleep`.
