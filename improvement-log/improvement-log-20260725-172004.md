### 2026-07-26 — axdriver `--action` flag is undocumented in the macos-test skill

**What happened:** The skill documents `press` as AXPress-only, so triggering a context menu looked like an automatic Tier 3 (HID) escalation. Reading `main.swift` showed `runPress` accepts `--action` (line 655), defaulting to AXPress — so arbitrary AX actions are already supported.
**Why this matters:** The gap would have sent a routine verification to Tier 3, which takes over Eugene's cursor and needs his explicit OK. (AXShowMenu turned out unsupported by the SwiftUI element anyway, but that's a different reason to escalate.)
**What better looks like:** Document `--action` in the macos-test skill's Tier 2 command list, with the note that SwiftUI `.contextMenu` rows do NOT support AXShowMenu (`-25204`) — so context menus are a known Tier 2 blind spot.

### 2026-07-26 — Inferred /api/sessions/resumable semantics by trial

**What happened:** Checked "is a closed session still resumable?" against a session with no transcript (got 0), then against a live session (also 0), before realizing `resumable` lists sessions with transcripts that are NOT currently running.
**Why this was inefficient:** Two wasted probe rounds, and the first near-miss could have been read as "close destroys the transcript" — a wrong conclusion baked into user-facing alert copy.
**What better looks like:** For an endpoint whose filter semantics matter to a claim, read the handler in `serve.ts` first (one grep) instead of inferring from probe outputs. Matches memory [[probe-shape-before-scripting]] — extend it: probe the *contract*, not just the record shape.

### 2026-07-26 — Started reading desktop app source before probing reachability

**What happened:** Asked why the desktop client showed no sessions from the Pro, I opened `desktop/` to inspect host-discovery code in the same breath as the first `tailscale status` call. The actual answer was that the Pro is entirely off the tailnet — no code involved.
**Why this was inefficient:** For a "client can't see remote host" report, reachability is the cheapest discriminator and it splits the entire hypothesis space in one probe. Reading client source only matters if the host answers.
**What better looks like:** Layer-by-layer from the bottom: `tailscale ping` target + a known-good control peer → target's API port → only then client-side code. Confirm the transport before auditing the consumer.
