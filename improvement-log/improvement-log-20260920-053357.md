He replied "But I can't get to the Air how can I login?" — the session runs ON the Air and he drives it from his phone, so an OAuth flow that opens a browser and listens on `localhost:8976` was unreachable by construction. `wrangler login --device` (RFC 8628 device grant) existed the whole time and its own help text names this exact case: "Useful in containers, remote SSH sessions, or other environments where localhost:8766 is unreachable from your browser."
**Why this was wrong:** I proposed the default flow without asking whether the person driving the session can see that machine's screen. Every lfg session is remote by design — that is the product. An interactive-browser instruction is almost never executable here.
**What better looks like:** Before handing over ANY interactive auth step, assume no GUI on the host and look for the headless variant first (`--device`, `--no-browser`, a device code, or an API token). Read `<cmd> login --help` before suggesting `<cmd> login`.

### 2026-09-20 — A test caught a query string that would never have reached the server

**What happened:** I wrote `liveActivityChannel(env:)` as `send("GET", "api/push/live-activity/channel?env=\(env)")`. `LFGClient.send` builds its URL with `url(path)`, which appends a PATH component — so the "?" was escaped into the path and `request.url?.query` was nil. The XCTest assertion on `url.query` failed immediately; switched the endpoint to POST with the env in the JSON body, matching every other push endpoint in that client.
**Why this was nearly a real bug:** The server reads `url.searchParams.get("env")`, which would always have been absent, so every device would silently have been handed the sandbox channel — and a production card started against a sandbox channel does not start at all. It would have looked like "broadcast doesn't work".
**What better looks like:** This is the system working — the assertion on the parsed URL, not just the path, is what caught it. Worth keeping: when adding a client call with parameters, assert on the *parsed* request (method, path, query, body), never just the path. Also: before using a query string with an existing client helper, check how it builds URLs; `LFGClient` has no query support and no other caller uses one.
