### 2026-10-09 — Fork request rested on a premise the disk disproved

**What happened:** Eugene asked that "Fork session" also type `/branch` (claude) or `/fork` (codex), believing it only resumes. Before building, I checked the two most recent client forks on disk. Both were real forks: new ids, separate transcripts, codex `session_meta.forked_from_id` set, files diverged afterwards, separate rows in `/api/sessions`.
**Why it matters:** The literal build (resume X, then type the command) puts a second writer on the source session and, for a busy source, auto-continues the interrupted turn inside the source itself before the command lands. It would have been a regression dressed as a fix.
**What better looks like:** For "X doesn't really do Y" requests, check the last real instance on disk first. What the user likely misses is the *visible* signal (Claude's `/branch` adds "(Branch)" to the title and prints a banner; `--fork-session` shows nothing).

### 2026-10-09 — Homebrew codex reinstalled

**What happened:** `/opt/homebrew/bin/codex` exists again (0.159.2, linked Sep 30), newer than `~/.bun/bin/codex` (0.156.1). `codexBin()` picks the newest, so today's fork pane ran the Homebrew copy.
**Why it matters:** The 2026-09-06 policy is one codex per Mac (the bun copy). Two copies drift and caused the resume version-skew outage before.
**What better looks like:** Ask Eugene whether the policy changed; if not, remove the Homebrew copy and update bun's, or add a doctor check that warns on two installs.

### 2026-10-09 — zsh `=word` trap recurred

**What happened:** A cleanup line ran `tmux kill-session -t =lfg-forkprobe` unquoted. zsh treated `=lfg-forkprobe` as path expansion, printed "not found", and aborted the whole compound command. The evidence copy and tmux kill silently did not run.
**Why it matters:** The memory `zsh-bare-equals-word-aborts-command` exists, but tmux's `=` exact-match prefix is the most common way to write such a word, and recall did not fire.
**What better looks like:** Always quote tmux targets: `-t '=name'`. Worth adding the tmux case to that memory's description so recall triggers on "tmux -t =".

### 2026-10-09 — axdriver context menus

**What happened:** axdriver lists only `press`, but `press --action AXShowMenu` on a SwiftUI List row's button opens its context menu. It returns AXError -25204 even though the menu opens; the menu items are then pressable by identifier. `AXShowMenu` on the AXRow returns -25206 (unsupported).
**What better looks like:** Add this to the macos-test skill's verified gotchas, so the next agent does not escalate to Tier 3 for a context menu.

### 2026-10-09 — Shared desktop build dir during concurrent work

Building into `desktop/build` would also have raced that session. ### 2026-10-09 — Guard regex and `open -b`

**What happened:** One compound command did install steps and then `open -b com.eugenechan.lfg-desktop`. The flowdeck guard regex `open\s+.*\.app` matched across the whole line, because `/Applications/lfg.app` appeared after `open`. It blocked the entire command; nothing ran.
**What better looks like:** Launch apps by bundle id in a command of their own. Optionally tighten the guard to match only the `open` invocation's own arguments.

### 2026-10-09 — Proving a Swift literal is in a binary

**What happened:** `strings … | grep -c "Forking session"` returned 0 on a binary that contained the feature. Swift stores string literals of 15 bytes or fewer inline in code, not in `__cstring`.
**What better looks like:** Check a literal longer than 15 bytes, or run the binary's own feature test (`--desktop-feature-test`).

### 2026-10-09 — Air deploy: dependency missing, install blocked by VPN

**What happened:** Another session's uncommitted scheduled-tasks code added `croner` to package.json. On the Air, `bun install --frozen-lockfile` failed twice with `UNKNOWN_CERTIFICATE_VERIFICATION_ERROR` (registry traffic leaves via utun11; curl got `SSL_ERROR_SYSCALL`). A `bun build src/cli.ts` pre-flight showed `Could not resolve: "croner"` before the kill, so the server never went down. Fix: `rsync node_modules/croner/` from the Pro (same version, no deps), re-run the bundle, then restart.
**Why it matters:** The memory says "run bun install before the kill" but not that it can fail on the Air, and a failed install is easy to miss in a long command.
**What better looks like:** Make `bun build src/cli.ts --target bun` the gate before every remote restart; if install fails on the Air, rsync the missing packages from the Pro. Add both to [[air-ssh-access]].
