## Log

### 2026-09-19 — Bare `colorScheme` without an `@Environment` property

**What happened:** Applied `.chrome(colorScheme)` in `SessionDetailView` assuming the view already read `\.colorScheme`. It didn't; the name resolved to the `View.colorScheme(_:)` modifier and the build failed once.
**Why this was wrong:** I grepped for `colorScheme` in that file, saw no hits, and still used the name. The grep result was the answer.
**What better looks like:** When a grep for an identifier returns nothing, add the property in the same edit as the use.

### 2026-09-19 — FlowDeck lock-check false positive, again

**What happened:** `flowdeck ui simulator screen` waited 45s on "Simulator appears locked" while the sim was plainly on the session list. Memory [[flowdeck-lock-check-false-positive]] already records `FLOWDECK_UI_SKIP_LOCK_CHECK=1`.
**Why this was wrong:** Cost 45s and a session restart before I applied the known bypass.
**What better looks like:** Export `FLOWDECK_UI_SKIP_LOCK_CHECK=1` on the very first `flowdeck ui` command in any session; consider putting it in `.flowdeck/` or the shell profile so it is never forgotten.

### 2026-09-19 — Tapped before the relaunched list settled

**What happened:** After `flowdeck run` relaunched the app I tapped the session row after a 3s sleep; the tap reported success but the screen captured afterward was still the list. The row had moved because list order changed.
**Why this was wrong:** I trusted the tap's success flag over a fresh screenshot. Verify-after-every-action is the rule.
**What better looks like:** After a relaunch, `scroll --until <label>` then tap, then read the screenshot before capturing evidence.

### 2026-09-19 — Parallel TestFlight deploys, one from a clean worktree
