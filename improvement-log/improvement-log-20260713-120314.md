### 2026-07-14 — A clean textual merge hid a 12-error semantic conflict; the build is the real gate

**What happened:** Trial-merging the desktop-ssh branch into main produced ONE trivial 4-line
conflict (keep-both). It looked like a ~15-min reconcile. But `desktop/build.sh` then failed with
12 compile errors: main and the branch had forked the host model incompatibly (`[String]` settings
editor vs `HostEntry{url,ssh}`). `git merge`'s "success" said nothing about compilability.
**Why this matters:** merge-conflict-count is a terrible proxy for merge difficulty. Two branches can
auto-merge cleanly at the text level and still be semantically incompatible (types, API contracts).
The only honest "how hard" answer comes from building/testing the merged tree.
**What better looks like:** for any non-trivial merge, don't estimate from conflict count — resolve,
then BUILD/TEST the merged tree before quoting difficulty. I did this here (trial build) and it flipped
the estimate from "trivial" to "moderate, needs a model migration," which was the correct call.

### 2026-07-13 — Assumed "behind" when local main had actually DIVERGED (unpushed work)

**What happened:** Planned a fast-forward of the primary checkout to origin/main after
pushing Track B, calling local main "behind." The FF failed — local main had 2 unpushed
commits (a completed fork-transcript-loading feature) that diverged from origin/main at
`3fb7336`. Had to stop, reconcile via a real merge (one serve.ts conflict), verify, and
re-push.
**Why this matters:** I said "local main is behind origin/main" from a single
rev-parse comparison without checking ancestry. On a multi-session host, another session's
committed-but-unpushed work on main is common — "behind" vs "diverged" needs
`git merge-base --is-ancestor` BEFORE planning a FF or a restart-on-new-code.
**What better looks like:** Before any merge/restart/deploy that assumes linear history,
run `git merge-base --is-ancestor local origin` (and the reverse) to classify
behind/ahead/diverged. Budget for a reconcile merge on a shared-main host by default.

### 2026-07-13 — Assumed an env override was honored on a code path it wasn't

**What happened:** Built the live lease HTTP-seam test pointing the server at a temp
projects dir via `LFG_CLAUDE_PROJECTS_DIR`. The whole harness 404'd because
`resolveTranscript`→`findTranscriptById` hardcodes the real `PROJECTS_DIR`; only
`listResumable` honors the env var. Had to re-plant the fixture in the real
`~/.claude/projects` (uniquely-named temp subdir, cleaned on exit).
**Why this was wrong:** I grepped that the env var *existed* and assumed the resolve
path used it, instead of reading the specific function the seam calls end-to-end.
Violates [[probe-shape-before-scripting]] / [[ground-truth-before-hypothesizing]].
**What better looks like:** Before scripting a boot harness, trace the exact call the
route makes (here `foreignFresh`→`leasePath`→`resolveTranscript`→`findTranscriptById`)
to its concrete dir/IO, not just confirm a same-named env var exists somewhere in the file.

### 2026-07-13 — `timeout` not on macOS

**What happened:** First test invocation used `timeout 120 bun test …`; zsh: command not found.
**Why:** `timeout` is GNU coreutils, absent on stock macOS.
**What better looks like:** Use `bun test --timeout <ms>` (or `gtimeout` if coreutils
installed). Minor, recurring — worth a reflex.
