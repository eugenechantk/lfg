## Log

### 2026-09-28 — Full `bun test` run is SIGKILLed with no summary

**What happened:** `bun test` (whole suite) died with exit 137 right after `src/codex-bin.test.ts` output, twice, printing no pass/fail summary. Running each of the 100 test files alone: 1029 pass, 0 fail.
**Why it matters:** A suite that dies silently can't gate a push; every deploy has to fall back to a per-file loop (~minutes) to get a real verdict.
**What better looks like:** Bisect which file/test kills the shared process (likely a test that signals a pid/process group or trips a memory ceiling), fix it, and keep `bun test` as the one-command gate. Until then: `for f in src/**/*.test.ts; do bun test "$f"; done`.

### 2026-09-28 — Skipped improvement-log consolidation during session-cleanup

**What happened:** session-cleanup step 0 says to run `/consolidate-improvement-logs`, which deletes processed log files. Another session's log (`improvement-log-20260927-151438.md`) was modified 10 minutes earlier and a new twin log (`...-20260928-012549.md`) appeared seconds before this session's.
**Why it matters:** Consolidating mid-flight would delete a live session's observation journal.
**What better looks like:** session-cleanup should consolidate only logs whose mtime is older than some idle threshold (e.g. 6h), or skip consolidation when `lfg-sessions` shows other busy sessions in the same repo.

### 2026-09-28 — Bundle-id launch picked a stale evidence copy of lfg.app

**What happened:** After replacing /Applications/lfg.app on the Pro, `osascript -e 'tell application id "com.eugenechan.lfg-desktop" to launch'` started `.codex/evidence/claude-codex-handoff/lfg.app` (an old copy an audit left in the repo, untracked). LaunchServices had it registered with the same bundle id. `lsregister -dump | grep` to inspect hung past 60 s.
**Why it matters:** Any bundle-id launch (AppleScript, Dock, `open -b`) can silently run an old build, so a "deployed" desktop app may not be what's running. Verification by pid path caught it; a hash/mtime check of /Applications alone would not have.
**What better looks like:** Launch by path (`tell application "/Applications/lfg.app"`), then assert `pgrep -fl` shows `/Applications/...`. Evidence captures should not leave runnable .app bundles in the repo (zip them or `lsregister -u` after). Fixed today with `lsregister -u` on the evidence copy + `-f` on /Applications.

### 2026-09-28 — No sanctioned way to launch the Xcode-less desktop app

**What happened:** The FlowDeck PreToolUse guard blocks `open -a /Applications/lfg.app` and suggests `flowdeck run`, but the desktop app is a bare `swiftc` build (`desktop/build.sh`) with no Xcode project, so FlowDeck can't run it. Fell back to AppleScript `activate`.
**What better looks like:** Guard should exempt `/Applications/lfg.app` (or any .app without an xcodeproj), or `desktop/build.sh` should grow an `--install` flag that quits, replaces, registers and relaunches by path — the same 6-step sequence done by hand on both Macs every deploy.
