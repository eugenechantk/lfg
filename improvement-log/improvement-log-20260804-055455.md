### 2026-08-04 — Stale memory: "fix is uncommitted" was wrong

**What happened:** `lfg-pro-host-sleep-disconnects.md` asserted the instant-reconnect
fix was uncommitted in the working tree. It had since been committed (`7a5b2ea`) —
but *after* the `41ac525 ios: 1.2.0` version bump, with `MARKETING_VERSION` never
re-bumped. So the true state was "committed, never shipped", which points at a
completely different action (cut a build) than what the memory implied (land the code).
**Why this matters:** a memory that names a *transient* state (uncommitted, in-tree,
pending) goes stale silently and sends the next session down the wrong path.
**What better looks like:** when writing a memory about work-in-progress, record the
*durable* fact (which commit, which released version) rather than the working-tree
state, or explicitly date-stamp the volatile claim. Corrected in place.

### 2026-08-04 — Existing diagnoses weren't surfaced until directly asked

**What happened:** Eugene reported three connection symptoms. All three were already
fully diagnosed in `.claude/diagnosis-pro-disconnect-banner-20260804.md` and
`.claude/diagnosis-send-path-branch-panes.md`, written earlier the same day. The
runtime-migration conversation ran for three turns before those docs entered the

heuristic, not runtime.
**Why this was inefficient:** the first three turns analyzed "is Bun stable enough"

**What better looks like:** when a question is framed as "is our tech choice causing
our pain", grep `.claude/` for existing diagnoses of that pain *before* analyzing the
tech choice. The symptom docs constrain the answer more than the architecture does.

### 2026-08-04 — Recommended a fix that was already implemented

**What happened:** I told Eugene to "replace screen-scrape confirmation with a real
signal — confirm delivery by transcript growth." On finally reading `deliver()`, the
transcript-growth authority was already there (`sendq.ts:752-780`), with a comment
explicitly stating it does not require a composer re-match. The real gap was one step
earlier and much narrower: the *insertion* check treats an unreadable composer
(`null`) as failure.
**Why this was wrong:** I recommended an architectural change from a symptom summary
and two diagnosis docs, without reading the function I was proposing to change. The
recommendation was directionally right but wrong in substance, and if Eugene had acted
on it as stated he'd have rebuilt something that existed.
**What better looks like:** before recommending a change to a specific function, read
that function. Diagnosis docs describe what *was* fixed; they do not tell you what the
code does now. Cost here was low because I caught it before writing code — but only
because implementing forced me to read it.

### 2026-08-04 — TestFlight deploy blocked by an unsigned Apple agreement

**What happened:** `deploy_testflight` failed instantly at the first App Store Connect
call with "A required agreement is missing or has expired." Nothing built, nothing
uploaded. This is a legal agreement only the Account Holder can sign in the ASC web UI.
**Why it cost time:** worktree creation, env copying, and `bundle install` all ran
before hitting a blocker that a single API call could have detected up front.
**What better looks like:** the testflight-deploy skill should preflight ASC
reachability (a cheap `Spaceship::ConnectAPI::App.find`) *before* the worktree/bundle
setup, so an agreement or auth blocker surfaces in seconds rather than after setup.
Worth proposing as a skill change during the next `/self-improve`.
