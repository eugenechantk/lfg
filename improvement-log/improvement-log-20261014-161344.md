## Log

### 2026-10-15 — sed edits on artifact files echoed whole files back into context

**What happened:** Two small fixes to canvas artboards were made with `sed -i` through Bash. Each one triggered a "file changed on disk" notice that pasted the whole ~180-line artboard back into context.
**Why this was wrong:** It cost thousands of tokens for one-word fixes, and it happened twice before I switched.
**What better looks like:** For files already written in this session, use the Edit tool for small fixes. Better still, check data shapes (for example `{{n}}` on a string array) before the first Write.

**What better looks like:** When a design adds a status group or badge, draw the destination screen for each state in the same pass: healthy, failed, waiting for input, paused, and closed.

### 2026-10-15 — Dark-mode converter shipped two color bugs

**What happened:** My script that converted light artboards to dark replaced `rgba(255,255,255,0.96)` with the glass color before the gradient rule ran. The bottom fade on the dark task list became grey instead of black. A fill rule also turned the Tasks tab dot light. I only found both when I re-read the published file for the next change.
**Why this was wrong:** Rule order in a find-and-replace table matters. My leftover scan only looked for light hex values, so it could not catch a wrong dark value.
**What better looks like:** Put the most specific patterns first, such as the gradient stops before the bare glass color. After converting, grep for the known risky outputs (`rgba(44,44,46,0.92) 5`, `fill="#D1D1D6"`), not only for leftover light colors.

### 2026-10-16 — A CSS quirk in my own board became a verifier failure

**What happened:** In the Mac "Show more" board, the toggle's rail column was `flex: 0 0 14px` with a 16px disc inside. Flex items default to `min-width: auto`, so the column grew to 16px and the label sat 2pt right of the run text. The app lined the label up with the run text (as the phone board does), and round 2 failed on that 2pt.
**Why this was wrong:** The board is the ground truth. An authoring accident in it costs a full verifier round and can push the app toward a layout nobody intended.
**What better looks like:** When a board puts a larger child in a fixed-width column (a disc on a rail), set `min-width: 0` on the column. Before publishing interactive boards, zoom-check the alignment of new rows against existing rows in the local render.

### 2026-10-16 — The FlowDeck guard blocks launching the installed Mac app

**What happened:** Installing the new desktop build into /Applications, the relaunch `open /Applications/lfg.app` was blocked by `flowdeck-guard.sh` ("FlowDeck provides this functionality"). FlowDeck's `run` has no option to launch a prebuilt app, and lfg's desktop app is built with swiftc, not an Xcode scheme. I relaunched it with `osascript -e 'tell application id "com.eugenechan.lfg-desktop" to activate'` and said so.
**Why this matters:** The guard exists to route development builds through FlowDeck and keep simulators isolated. Launching the user's daily-driver app is outside that purpose, so the block is a false positive that pushes agents toward workarounds.
**What better looks like:** Teach the guard to allow `open /Applications/<app>.app` (installed apps), or document the AppleScript `activate` path as the sanctioned way to relaunch an installed Mac app. A small `scripts/install-desktop.sh` (build, quit, back up, ditto, relaunch, copy to the Air over ssh) would make this a one-liner.
