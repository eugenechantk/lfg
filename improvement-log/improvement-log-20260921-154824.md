### 2026-09-21 — Shipping an uncommitted patch via the deploy worktree recreates the known dirty-tree regression hazard

**What happened:** Asked to hide the browser preview and cut a build. "Never commit unless asked" meant the flag edit was applied to `~/build/lfg-testflight` with `git apply` rather than committed, so the shipped build's source is HEAD + an uncommitted patch.
**Why this matters:** Memory `clean-worktree-build-drops-dirty-tree-features` records this exact shape regressing twice: the next archive from a clean HEAD silently un-hides the feature.
**What better looks like:** A "change X and cut a build" request should be read as including the commit of X, or the deploy workflow should state that rule. Candidate CLAUDE.md line: a TestFlight request authorises committing the change it ships.
