### 2026-09-27 — Wrote the Codex picker driver from a partial probe; live runs found 3 bugs

**What happened:** I probed Codex's /model → reasoning screens once (current level High), then wrote `switchCodexEffort` and unit tests from trimmed copies of those panes. Live runs then failed three ways: (1) the `s session` hint follows the highlighted row, so it is absent when "More reasoning… (current)" is highlighted; (2) `parsePrompt` ignores one-row selectors, and Luna's "Advanced Reasoning" has only Max; (3) Ultra changes Codex's composer glyph to `»`, which no lfg pane parser knew. A fourth came from the journal: lfg's own drive was emitted as a "needs input" prompt.
**Why this was wrong:** A driver for an external TUI depends on every state the TUI can be in when the driver starts. I probed only one starting state and one model.
**What better looks like:** Before writing a TUI driver, probe the matrix: each starting state (every current value, including ones behind submenus) × a model with fewer options, and read the journal/push logs during a manual run to see what else observes the pane. Keep the captures as fixtures verbatim; trimming removed the blank line that mattered.

### 2026-09-27 — Hit the zsh bare `=====` trap despite a memory about it

**What happened:** `echo ======` in a compound command aborted the rest with "===== not found"; the memory `zsh-bare-equals-word-aborts-command` already records this.
**Why this was wrong:** The memory index was loaded but did not come to mind while writing a throwaway separator.
**What better looks like:** Never use bare `=`-leading words as separators; use `echo "---"`. Consider a PreToolUse hook that warns on `echo =`.

### 2026-09-27 — `cd ..` inside a Bash call moved the primary working directory

**What happened:** `cd /Users/.../lfg/.. && ...` changed the session's primary cwd to `~/dev/personal` (the harness persists cwd).
**What better looks like:** Use absolute paths or a subshell `( cd … && … )` for one-off directory changes.

### 2026-09-27 — Used a `$S` UDID variable in flowdeck calls despite the memory

**What happened:** Batched five flowdeck calls behind `S=<udid>`; the guard blocked all of them. Memory `flowdeck-sim-guard-cwd` already says: literal UDID, one flowdeck call per Bash command.
**What better looks like:** Treat that memory as a hard template: every flowdeck call gets the literal `-S "<udid>"`, one per Bash call. A PreToolUse hint that names the memory when it blocks would shorten the loop.

### 2026-09-27 — Tapping the real menu caught a staleness the API checks missed

**What happened:** Every curl read-back after a Claude effort change was correct, but tapping the phone menu right after a change showed the old level for ~15 s: the client refreshes on the reply while the old Claude process is still exiting (and the new one has no pidfile yet). Fixed server-side (`awaitRelaunched`).
**Why it matters:** Confirms memory `verify-ui-by-tapping`: the client reads at a specific moment (right after the reply), and API probes taken seconds later can't see that window.
**What better looks like:** For any action whose reply triggers a client refresh, probe the read-back IMMEDIATELY after the reply in the same shell command, not after a sleep.
