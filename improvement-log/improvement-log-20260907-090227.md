## Log

### 2026-09-07 — Probe commands died on shell quoting

**What happened:** `grep --include=*.swift` (zsh globbed it), a python `-c` f-string with `\"` inside, and `ls -d */*/subagents` (project dir names start with `-`) each failed once, costing a round-trip apiece.
**Why this was wrong:** Memory `probe-shape-before-scripting` already says write the probe to a file first. Inline one-liners under zsh keep breaking on the same three things.
**What better looks like:** Put any probe longer than one pipe into a scratchpad `.py` file (as `probe.py`/`watch.py` eventually were); use `find` not `ls` under `~/.claude/projects`; quote `--include='*.swift'`.

### 2026-09-07 — Hypothesised from source before probing live

**What happened:** Walked list-count → journal → decode → menu-deferral → duplicate-transcript hypotheses from source for a long stretch; the live spawn-two-agents probe (2 minutes, zero disagreement on the Pro) and the cross-host `ls` (peer has no transcript) settled it faster than any of them.
**Why this was wrong:** `ground-truth-before-hypothesizing` memory. Server-vs-client split is the first fork; one live probe answers it.
**What better looks like:** For "list says X, detail says Y" reports: (1) spawn the discriminating case and poll both endpoints, (2) ask which host served each read, (3) only then read source.

### 2026-09-07 — Two-host outage rig in the simulator was the wrong tool

**What happened:** To get a discriminating control for the child-agent routing fix I fronted the Pro with a local proxy, then had to make the Air the default, remove the bundled tunnel entry for the Pro (it is re-added on every launch), and drive Settings by raw HID taps. Removing that entry hid the machine's live rows (a separate quirk), so the control never ran cleanly. ~45 minutes, ~40 tool calls.
**Why this was wrong:** The routing rule is a pure function that was already unit-tested against exactly the peer-404 case, and the diagnosis had live evidence that the peer 404s. The sim adds nothing to that specific claim; it only proves rendering, which the first positive run already did in 10 minutes. `verify-the-discriminating-case` is about choosing the scenario, not about insisting every scenario be end-to-end.
**What better looks like:** Decide up front which criteria need the real seam and which are pure logic. For multi-host client behaviour, a rig needs the machine to be reachable through ONE entry only — the bundled tunnel host makes that impossible in a stock build, so either accept unit-level proof or add a launch flag that disables bundled hosts (worth proposing).

### 2026-09-07 — Subagent harness blocks `sleep`

**What happened:** Two probe sessions asked child agents to run `sleep 150`/`sleep 300`; both reported "completed" within seconds because a hook refuses `sleep` in the Bash tool. Third try used `python3 -c "import time; time.sleep(420)"`, which ran.
**Why this was wrong:** I never checked the agents' actual output before relying on their "running" state; the first watcher log even showed the status flip early.
**What better looks like:** When a probe depends on a child doing X for N minutes, verify X actually started (pane/transcript) before building on it, and use a sleep that hooks do not block.
