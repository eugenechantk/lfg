### 2026-10-08 — Read "still running" as `busy` and chased four busy layers before checking `status`

**What happened:** Eugene said two errored SleepingBeauty sessions were "still running". I assumed the `busy` flag and checked the hook layer, transcript turn_duration, REST busy, journal deltas, subagent sidecars and the offline-Air snapshot path. All said idle. The real cause was `status: "blocked"`: the ECONNRESET line carries `error: "server_error"`, and `computeStatus` graded every coded error as an unknown block, so the app showed "Build paused".
**Why this was slow:** The journal `msg` event I had already printed showed `errorCode: "server_error"`. The app has THREE non-idle states (needs input, paused, working), and a user calls any of them "running".
**What better looks like:** For "session shows the wrong state" reports, first resolve the full display ladder for that session (prompt, status/blocked, busy, closed) from the live API, then dig into the one layer that is non-idle. Do not assume which word maps to which field.

### 2026-10-08 — `StopFailure` hook not registered

**What happened:** `~/.lfg/bin/lfg-agent-hook.py` maps `StopFailure` to idle, but `~/.claude/settings.json` registers only Stop/UserPromptSubmit/SessionEnd and others. An API-error turn end therefore leaves the hook layer at "running".
**Why it matters:** Today the transcript's `turn_duration` wins by recency, so it is masked. If a future Claude Code drops `turn_duration` after an error turn, sessions would latch busy for 15 min (STALL_MS).
**What better looks like:** Register `StopFailure` in `scripts/install-agent-hooks.py` and settings.json on both hosts, then commit ~/.claude.
