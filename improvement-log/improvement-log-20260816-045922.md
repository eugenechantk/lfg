### 2026-08-16 — FlowDeck sim guard blocks shell variables in `-S`

**What happened:** After the guard handed back this session's UDID, I set `SIM=5361ED19-…` and ran `flowdeck ui simulator tap -S $SIM …`. The PreToolUse guard rejected it with "this command targets '$SIM'" — it pattern-matches the literal command string before the shell expands anything. Two calls lost.
**Why this was wrong:** Memory `flowdeck-sim-guard-cwd` says "use the literal UDID the guard returns" and I read it as being about not `cd`-ing. It is also literally about the literal string.
**What better looks like:** Paste the raw UDID into every flowdeck invocation, even when it appears six times in one command line. No variables, no `$()`.

### 2026-08-16 — Label-based tap hit the wrong control

**What happened:** `flowdeck ui simulator tap "Search sessions"` opened the New Session sheet (the adjacent `+` button), and I typed a search string into a session-kickoff composer before noticing.
**Why this was wrong:** The label matched something other than the visible search field, and I trusted the "✓ Tapped: Search sessions" success line instead of verifying with a screenshot. Typing into an unknown focused field on a host full of live agents is exactly the kind of blind action that can start real work.
**What better looks like:** For any tap that precedes typing, use `--point` coordinates read off the screenshot I just captured, and screenshot again before typing. Reserve label taps for buttons whose action is idempotent.

### 2026-08-16 — `SessionStore.resume(_:on:)` has no UI caller

**What happened:** While wiring the new Restarting status I grepped for callers of the store's `resume` and found none — the only user-facing wake path is sending a message to a closed session; `transfer` uses the client directly.
**Why this matters:** Not a mistake, but it changes what "verified" means: success criterion 2 of the feature (explicit Resume with no message) is unreachable from the UI, so it was reported N/A rather than passed. It is also a small product gap — a "Resume" swipe action on a Closed row is now a one-liner.
**What better looks like:** When a feature doc lists a criterion, check there is a UI path to it *before* the live run, not during. Captured in `.claude/feature/restarting-status.md`.
