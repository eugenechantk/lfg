## Log

### 2026-09-08 — `zsh -c air` resolved to the port forwarder, not the alias
**What happened:** Ran the alias through `zsh -ic 'air ...'` under a pty; `~/.local/bin/air` (lfg-forward symlink) won and printed usage. Three runs wasted before noticing.
**Why this was wrong:** Aliases only exist in interactive shells with a tty-driven rc; a same-named binary on PATH shadows them elsewhere. I should have `type air` first in the exact shell shape I was about to use.
**What better looks like:** Resolve the name once (`zsh -ic 'type air'` under the pty) and then invoke the resolved command (`mosh-bridged air`) directly.

### 2026-09-08 — Verified with the wrong path
**What happened:** Three green `mosh-bridged air` runs used the LAN fast path (Pro was back on the home LAN), which bypasses the Cloudflare tunnel I had just changed.
**Why this was wrong:** Violates [[verify-the-discriminating-case]] — the old, broken config would also have passed those runs.
**What better looks like:** For any tunnel change, verify with `LFG_MOSH_NO_LAN=1` and a held session (~100s), and read the bridge log line that names the path taken.

### 2026-09-08 — One-shot probe said healthy; the log said flapping
**What happened:** `ssh air hostname` succeeded in 0.5s and I nearly concluded the alias was fine. The tunnel logs showed ~500 re-registrations/day.
**Why this was wrong:** An intermittent 60s flap is invisible to a 0.5s probe. The count of `Registered tunnel connection` per day was the real signal and took one grep.
**What better looks like:** For connectivity reports, read the daemon's own log churn before trusting a probe. Saved as memory [[cloudflare-tunnel-quic-flaps-under-vpn]].

### 2026-09-08 — Commit loop false failures
**What happened:** The retry loop's remote command ended in `cat deadman.log`, which doesn't exist on success, so the `&&` chain returned non-zero and the loop reported "failed" 3 times even though the commit file was written on attempt 1.
**Why this was wrong:** Confused a successful commit with a failed one; I only learned the truth on the next turn.
**What better looks like:** Put the commit step last and make optional reads `|| true`; print the state explicitly instead of inferring from exit codes.

### 2026-09-09 — Nested quoting in `ssh 'cmd <<EOF … EOF'`
**What happened:** A heredoc containing `Mac's` inside a single-quoted remote command needed `'"'"'` escaping; the first attempt failed with a parse error before writing anything.
**Why this was wrong:** Two quoting layers plus a heredoc is fragile. For a config file that already exists on the local machine, `scp` then `mv` on the remote is one layer.
**What better looks like:** Push files, not heredocs, through ssh whenever the content exists locally.

### 2026-09-09 — Wrong `<address>` from Syncthing config.xml
**What happened:** `grep -o "<address>" | head -1` returned the device's `dynamic` address; curl to `http://dynamic/...` returned nothing and every python parser threw.
**Why this was wrong:** I didn't eyeball the raw match before piping it ([[probe-shape-before-scripting]]).
**What better looks like:** Scope the sed to the `<gui>` block; it's `127.0.0.1:8384` on both Macs. Recorded in the cleanup plan doc.

### 2026-09-09 — Blocking rescan
**What happened:** `POST /rest/db/scan?folder=dev` did not return until the scan of ~90 GB finished; the ssh wrapper timed out at 120s and I lost the verification output.
**What better looks like:** Fire the scan with `--max-time 5` (the scan continues server-side) and poll `/rest/db/status` until `state=idle`, then read ignores/file status.
