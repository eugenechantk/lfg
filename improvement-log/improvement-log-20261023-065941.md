### 2026-10-23 — Removed the card to fix alignment; the card was the part Eugene liked

**What happened:** To align the pane's buttons with the transcript bar, I moved the header out of the card and floated it on black. Eugene asked to revert. I then kept the card and aligned it the way the sidebar card already does: the header row is the card's top 44pt, with plain icons.
**Why this was wrong:** I fixed one property (alignment) by changing the overall look (the container), and he had asked only for the alignment. The sidebar card next to the pane already solved the same problem without losing the card. I didn't look at how the neighbouring component did it.
**What better looks like:** When asked to align or tweak, change the smallest thing, and copy how a neighbouring component already solves it before inventing a new structure. If the fix needs a visible style change, show both options before publishing.

### 2026-10-23 — Proposed viewer actions lfg has no use for

**What happened:** The pane's header and ••• menu carried Share, Open in new window and a Preview/Source toggle, all taken from the research (Claude, Apple HIG Windows). Eugene asked what "a new window" even means in lfg and removed all three.
**Why this was wrong:** It is the same mistake as the S1 Mobbin copy on 2026-10-15: I imported patterns from other products without checking that lfg has the concept (lfg has one window) or that Eugene wants the density. Memory [[lfg-design-preferences]] already says "only draw what the product really has".
**What better looks like:** For every control taken from research, name the lfg concept it acts on and the job Eugene does with it. If either is missing, leave it out. Saved as rule 16 in lfg-design-preferences.

### 2026-10-23 — Brace-halving bug from patching an f-string generator

**What happened:** I patched `gen.py` with a Python script whose replacement strings were f-strings themselves. One `{{{{showExpand}}}}` became `{{showExpand}}` in gen.py, which then rendered as `value="{showExpand}"`. The bug was published in version 105 and fixed in version 108. My screenshot check passed because the button still happened to show in landscape.
**Why it matters:** A malformed hole fails silently in the DC runtime. A screenshot only catches it when the state it controls looks wrong.
**What better looks like:** After every generator run, grep the output for single-brace holes (`[^{]\{[a-zA-Z.]+\}[^}]`) and for leftover placeholders. It costs one command. Better still, avoid f-strings inside patch scripts.

### 2026-10-23 — Pane buttons 10pt below the transcript bar

**What happened:** The pane's header sat inside its card, which starts at y=42, so its buttons were centred at y=74. The transcript bar and the sidebar header are centred at y=64. Eugene saw the step at a glance.

**What better looks like:** When a new column joins a layout, measure the centre line of its top controls against its neighbours before publishing. Saved as rule 17 in lfg-design-preferences.

### 2026-10-23 — One interactive board + importer boards per state

**What happened:** For the iPad file pane I built a single interactive `ia-proto.dc.html` holding every state (open file, width, focus, overlay, menu, layout A/B/portrait/13-inch). The 15 static boards are 700-byte files that `dc-import` it with a `start`/`layout` prop.
