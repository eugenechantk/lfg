### 2026-11-04 — Sheet onDismiss saw a stale window size

**What happened:** Rotating the iPad with the portrait file sheet open closed the file. `onDismiss` ran `if presentation == .sheet { close() }`, and `presentation` is computed from `navigation.windowSize` (an `@Environment` value). The closure is kept from when the sheet appeared, so it still saw the portrait size. Docking never hit it because `portraitDocked` comes through the live `@Binding`. Fixed with a `@State` flag set when the layout takes the sheet away.
**Why it matters:** The bug predates today's work and survived the Oct 25 audit because no test rotated with a sheet open. My first version of today's full-screen change only patched the full-screen case in the same closure.
**What better looks like:** In a presentation's `onDismiss`/completion closure, read only `@State`/`@Binding`/observable state, never values derived from `@Environment` or plain `let`s. For any adaptive layout, add one UI test that rotates with each presentation open; run it against the old code once to prove it discriminates.
