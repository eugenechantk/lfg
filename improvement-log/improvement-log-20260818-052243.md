## Log

### 2026-08-18 — Compared builds with an unverified stimulus

**What happened:** Profiled scroll performance before/after using
`flowdeck ui simulator swipe down --distance 0.7`. Only later, when a screenshot
pair came back byte-identical, did I discover that FlowDeck's *directional* swipe
form lands in the composer on this screen and scrolls nothing. The first
before/after table was built on a stimulus that barely moved the view.

**Why this was wrong:** A performance comparison is only as good as the identical
work both sides do. I verified the *measurement* tool (`sample`) carefully and
never verified the *stimulus*. The numbers were not fabricated, but they measured
the wrong thing, and I nearly reported them.

**What better looks like:** Before profiling any interaction, prove the
interaction happens — one screenshot diff (`md5` of two captures) costs seconds.
For FlowDeck specifically: use explicit `--from`/`--to` coordinates inside the
scrollable area, not the directional shorthand, on any screen with a composer or
bottom bar.

### 2026-08-18 — Declared paging broken from screenshots alone

**What happened:** After adding the load-earlier window, two screenshots showed
the loader row still on screen with identical content below, and I concluded the
extend never fired. Adding one `print` and reading `flowdeck logs` showed the
window walking 200 → 400 → 600 → 800 → 1000: it was firing on *every* swipe. The
real bug was the opposite of my read — a runaway, not a no-op.

**Why this was wrong:** Two screenshots of a state machine mid-flight are
ambiguous; "nothing happened" and "it happened five times and restored the view"
look identical. I had the repo memory for this (`ground-truth-before-hypothesizing`)
and reached for a second screenshot instead of a log line.

**What better looks like:** When a state machine's behavior is in question,
instrument it before interpreting pixels. A temporary `print` plus
`flowdeck logs <app-id>` is a ~90 second loop and turns a guess into a count. Note
`flowdeck logs` needs the short App ID — the bundle id matches every past run and
errors out.
