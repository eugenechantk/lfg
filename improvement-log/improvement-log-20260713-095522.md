## Log

### 2026-07-13 — `ts` unit was wrong in the exploration report

**What happened:** Adding a sent-time caption under the iOS user message bubble. The Explore agent that mapped the code confidently described `SessionMessage.ts` (`Double?`) as "epoch seconds (Unix time)". I built the formatter with `Date(timeIntervalSince1970: ts)` on that basis. The first live render showed "Sep 11, **58500** at 7:17 AM" — the value is actually epoch milliseconds (13 digits, e.g. 1783445698997).
**Why this was wrong:** I trusted a subagent's inferred unit for a numeric field instead of checking a real value. The struct field is just `Double?` with no unit annotation, so the agent guessed — and guessed wrong.
**What better looks like:** For any epoch/duration/unit-bearing numeric field, confirm the unit against a real record (one `curl` of the API showed 13-digit ms immediately) before writing formatting code. This is the [[probe-shape-before-scripting]] principle applied to units, and live UI verification ([[verify-ui-by-tapping]]) is what caught it — a mocked test with a hand-picked timestamp would have hidden the bug.
