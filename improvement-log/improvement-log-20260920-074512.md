### 2026-09-20 — `git pull origin` fails on the checklist step

**What happened:** Step 1 of the Session Start Checklist (`git pull origin`) exited with
`fatal: Need to specify how to reconcile divergent branches.` main was ahead 1 / behind 2 with a
dirty tree holding other agents' work, so I fetched only and left the merge alone.
**Why this is friction:** The checklist prescribes `git pull origin` unconditionally, but on lfg
main routinely diverges and the tree is routinely dirty with concurrent agents' uncommitted work —
the exact situation where an automatic merge or rebase is the wrong move. The step either fails
loudly (today) or, with a reconcile strategy configured, would silently merge into someone else's
working tree.
**What better looks like:** For repos with concurrent agents, the checklist step should be
`git fetch origin` + report divergence, and leave merging to an explicit decision. Worth raising
in `/self-improve` as a global CLAUDE.md amendment rather than a per-repo workaround.

### 2026-09-20 — A prefix heuristic silently deleted real user turns

**What happened:** `userTurnFromLine` (`src/sessions.ts`) drops any user turn whose text
`startsWith("<")`, on the reasoning that `<command-name>` / `<local-command-stdout>` are Claude Code
machinery rather than the human. Claude Code 2.1.278 then began wrapping bracketed-paste input in
`<pasted_content id="…">…</pasted_content id="…">`. Because lfg delivers *every* multi-line phone
message by bracketed paste, every one of those turns started with `<` and vanished from session
titles and the user-turn digest. Nothing logged, nothing failed — the turns were simply absent.
Eugene noticed the *cosmetic* half (tags visible in the bubble); the data-loss half was found only
by reading the surrounding code.
**Why this was a latent bug, not bad luck:** The heuristic classified by *shape of a prefix* against
an open-ended upstream format. Any new wrapper Claude Code introduces is, by construction, a false
positive. It also failed in the silent direction: dropping a turn produces no error, no empty state,
no log line — the only symptom is an absence nobody can see.
**What better looks like:** Two things. (1) When a check discards data based on a prefix/shape match
against a format someone else owns, match a **closed set** of known wrappers, not an open prefix —
or log the discard. (2) When the user reports a cosmetic symptom of an upstream format change, grep
every consumer of that same string before fixing the visible half; the format change usually has a
second, quieter consequence. Here the fix (`unwrapPastedContent`, called from `stripHumanPrefix`)
lands ahead of the `startsWith("<")` check and repairs both at one seam.
