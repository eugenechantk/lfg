## Log

### 2026-07-26 — Relaunched MacCommandCenter without inventorying its runtime state

**What happened:** To ship the repoPath fix I quit-and-relaunched MacCommandCenter on the Pro and the Air. The app's keep-awake toggle (`keepAwakeWhenPluggedIn`) is in-memory only — not persisted — so the relaunch silently dropped the `caffeinate -i -s` hold on both machines, which both run `pmset sleep 1` with no SleepDisabled. The July 14 log had already established that hold was load-bearing for the Air. I only caught it during post-deploy verification and had to restore the holds manually (`caffeinate -i -s -w <app pid>`).
**Why this was wrong:** Restarting a long-lived process destroys whatever non-persisted state it holds. I checked signing/TCC implications before the swap but not runtime state (assertions, toggles, child processes). A sleep during the gap would have taken down an lfg host.
**What better looks like:** Before restarting any long-lived app/daemon, snapshot what it's currently holding (`pmset -g assertions`, child processes, in-memory config) and plan restoration of anything non-persisted. For MacCommandCenter specifically: the real fix is persisting the awake toggles (done this session — UserDefaults + reconcile-on-launch).

### 2026-07-26 — Codex delegation path broken (CLI out of date)

**What happened:** Delegated the ~20-line toggle-persistence change to Codex twice per the brain/hands routing policy. Both failed at the API level: Codex CLI on the Pro is out of date and the API 400s on its default model (`gpt-5.6-sol`), demanding an upgrade. Fell back to implementing inline (justified by the routing policy's "delegation overhead exceeds the work" carve-out — a broken delegation path that needs a CLI upgrade first clearly qualifies).
**Why it matters:** The whole cross-harness routing assumes Codex is available. When its CLI drifts, every delegation silently costs two failed round-trips before falling back. 
**What better looks like:** (1) Upgrade the Codex CLI on the Pro (and check the Air). (2) Consider a fast pre-flight `codex` health check before delegating, or treating a model-version 400 as an immediate inline-fallback signal rather than retrying.

### 2026-07-26 — Right-click close feature was uncommitted WIP on one host only

**What happened:** Eugene said the desktop app should have a right-click close-session feature "not in the current build." The Pro's committed source and working tree had no such feature. Found it only after checking all branches, worktrees, stashes, and finally SSHing to the Air — where it was uncommitted (`M desktop/LFGSessions.swift`). Brought the diff over as a patch, built, and deployed to both hosts.
**Why it matters:** Multi-host + uncommitted WIP = features that are invisible from the machine you're on and one `git checkout` away from being lost. This is the exact multi-host hazard in CLAUDE.md.
**What better looks like:** When a "missing" feature is expected but absent locally, check the OTHER host's working tree early (not last). And flag uncommitted-WIP-on-one-host to Eugene so it gets committed/pushed before it's lost.
