### 2026-10-05 — A finished iOS fix sat uncommitted for 6 days and shipped only by accident

**What happened:** Eugene reported that code blocks wrap and sit indented in the transcript (session lfg-f7bcd4). A session on 2026-09-29 had already written the fix: a separate code section in `SelectableMarkdownSections` and a horizontal `ScrollView` in `ProseView`, with tests and before/after screenshots in `.claude/codeblock-scroll/`. That session never committed it. The 09-30 TestFlight build came from a clean worktree, so the fix was missing. Build 202610042224 picked it up only because that deploy happened to archive the dirty main tree. I spent the first part of this session working out which build had which code by running `strings` on the archived binaries.
**Why this was wrong:** Nothing records that a fix is done but not on main. A clean-worktree deploy drops it silently, and the next bug report looks like a new bug. This is the third time (see memory clean-worktree-build-drops-dirty-tree-features).
**What better looks like:** When a session ends with a verified fix, it should ask to commit before it stops, or write a one-line "uncommitted, verified" note into a ledger the deploy lane reads. A deploy lane could also print the dirty files it archives, so an accidental inclusion is visible. Fast triage for "is the fix in build N": run `strings` on the archive binary and look for a new enum case name (here the run `prose`, `table`, `code`).
