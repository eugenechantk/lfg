### 2026-07-13 — Typed into unfocused composer, then retyped → doubled text

**What happened:** In the fork detail view, `flowdeck ui simulator type` reported success while the composer wasn't focused; nothing appeared, so I tapped the field and typed again — then BOTH types landed, sending a doubled message.
**Why this was wrong:** The first type wasn't lost, just delayed/queued until focus arrived. I retyped without re-reading the screenshot after the focus tap settled.
**What better looks like:** After a failed-looking type, tap to focus, wait, re-read the screenshot FIRST — only retype if the field is verifiably still empty.

### 2026-07-13 — Notification dialog tap-by-label missed silently

**What happened:** `tap "Allow"` on the iOS notification permission dialog returned success but the dialog stayed up; a coordinate tap at the button frame worked.
**Why this matters:** System dialogs (springboard-owned) aren't reliably hittable by label through the in-process tree; the project CLAUDE.md already warns about this class of trap for nav-bar buttons.
**What better looks like:** For system dialogs, go straight to coordinate/raw-HID taps and verify via screenshot.

### 2026-07-13 — Codex CLI too old for its configured default model

**What happened:** First /codex:rescue background job died in 20s: "The 'gpt-5.6-sol' model requires a newer version of Codex." Relaunched pinned to `--model gpt-5.5`, which the installed CLI accepts.
**Why this matters:** The delegation path silently burns a launch round-trip whenever Codex's default model config drifts ahead of the installed CLI. Failure is only visible on the first status poll.
**What better looks like:** Upgrade the Codex CLI (route through Codex itself once healthy, or ask Eugene), or pin a known-good model in the rescue invocation until upgraded. Consider a note in the codex-delegate skill's gotchas.

### 2026-07-13 — Worktree outside repo root blocked Codex writes

**What happened:** Created the feature worktree as a sibling (`../lfg-fork-fix`); Codex's sandbox only grants writes under the main repo root, so the first full delegation run ended with "operation not permitted" and zero files changed. Moved the worktree to `.worktrees/fork-fix` inside the repo and resumed.
**Why this was wrong:** Cost a complete Codex round-trip (~4 min + relaunch). The sandbox root constraint is knowable in advance.
**What better looks like:** Always create delegation worktrees INSIDE the repo (`.worktrees/<name>`, gitignored). Candidate addition to the codex-delegate skill.

### 2026-07-13 — Forked a busy session as a test; fork started doing real work

**What happened:** For the criterion-3 leak test I forked the actively-working live-activities session. The fork auto-continued the interrupted turn — running Bash tool calls in `/Users/eugenechan/dev/personal/lfg` — until I killed it.
**Why this matters:** A "read-only" verification fork of a busy session is NOT inert; it executes. In a shared repo with concurrent agents that can produce conflicting edits.
**What better looks like:** When a test requires forking a busy session, kill the fork tmux session immediately after capturing the needed data, or fork a busy session whose cwd is disposable.
