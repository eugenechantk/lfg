### 2026-09-16 — Server restart expired another agent's waiting sign-in request

**What happened:** Deploying this feature meant restarting `lfg serve`. `PhoneSignInRequests` is host memory; on boot, history rows that were `waiting` are stamped `expired`, and the Chrome extension reconnects with a new target id. Session 5c347955 had a live App Store Connect sign-in request (6bbfc5e5) that expired under it; the agent re-requested a minute later (64a67ad1).
**Why this matters:** A restart is not free for in-flight sign-ins, the same way it drops in-memory session tracking. Nobody checked the request list before restarting.
**What better looks like:** Before restarting the server, `GET /api/browser-sign-in/requests?sessionId=…` across live sessions (or read `~/.lfg/phone-sign-in-history.json` for `waiting` rows) and wait or warn. Candidate for a pre-restart check in `serve-forever.sh` / a deploy note in `.claude/CLAUDE.md`.

### 2026-09-16 — Push watcher tick takes ~70s per alert

**What happened:** `runPushTick` sends each alert push to every registered device sequentially (`for (const d of devices) await deps.send(...)`); `/api/push/health` reports 99 devices, 4 of which fail every time with `DeviceTokenNotForTopic` (pruned on the Live Activity path but not the alert path). The sign-in prompt appeared at 13:35:05Z; the Live Activity decision for that same tick logged at 13:36:16Z. Evidence: `/private/tmp/lfg-serve.log` (four `[push] … 400 DeviceTokenNotForTopic` lines per alert), `~/.lfg/liveactivity.log`.
**Why this matters:** The needs-input push reaches the real phone somewhere inside that 70s window, and the card lags a full tick. Pre-existing, not introduced here, but it caps how "immediate" the new prompt-while-busy notification can feel.
**What better looks like:** Prune `DeviceTokenNotForTopic` on the alert path like `isDeadApnsToken` does for Live Activities, cap the device list (stale tokens), and send with bounded concurrency. Separate task.

### 2026-09-16 — Unquoted glob aborted a compound grep

**What happened:** `grep -rln … --include=*.md --include=*.ts` under zsh failed with `no matches found: --include=*.md` and the rest of the `;`-joined command never ran, so the skill-template search silently produced nothing on the first try.
**Why this was wrong:** Memory `zsh-bare-equals-word-aborts-command` already covers `=word`; unquoted globs are the same failure class (zsh aborts the whole compound command on a failed glob).
**What better looks like:** Quote every `--include='*.md'` / glob argument, or use `setopt nullglob` semantics; one memory entry should cover both shapes.
